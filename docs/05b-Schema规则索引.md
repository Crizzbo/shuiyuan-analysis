## 1. 规则表达与执行责任

本索引的编号用于文档追踪，**不是校验器已经输出的错误代码**。当前工具返回消息文本。编号固定后应保留历史含义；废弃规则应标记废弃，不应重新分配编号。

“结构校验”指项目研究校验器已支持的 Schema 子集，不代表完整通用 JSON Schema 实现。“研究校验”指同一研究内的语义检查。“入库校验”指来源与历史版本检查。“人工复核”不自动阻断程序。任何一次 PASS 只覆盖该次调用实际执行的层次。

## 2. 结构与研究规则

| 编号 | 适用对象／条件 | 规范要求 | 执行责任 | 失败后的处理 |
|---|---|---|---|---|
| STR-001 | 所有实例 | 必填属性必须出现，类型、枚举、固定值和数组长度符合相应 Schema；不得增加未定义业务属性 | 结构校验 | 按精确字段定义修正 |
| STR-002 | 数字及 JSON 解析 | 不得使用重复键、NaN、Infinity 或以布尔值冒充数值 | 研究校验 | 修正序列化及原始值 |
| REF-001 | 各登记表及引用字段 | 对象 ID 在所属登记表唯一；引用必须存在于对应登记表，不得混用指标与观测 ID | 研究校验 | 修正对象身份和引用 |
| REF-002 | assumption_refs | 必须引用 assumption 类型判断；判断依赖不得形成循环 | 研究校验 | 拆分假设、事实和推断 |
| LOC-001 | 证据及实现路径 | 必须指向项目内存在的文件；解析后的真实路径不得越界 | 研究校验、入库校验 | 使用合规项目内文件 |
| TIME-001 | 时间及精度字段 | 非空 date-time 必须有效且带时区；日期须为有效日历日期；1.1.0 按 instant/date/unknown 核对精确时间与日期的组合，精确时间及日期同时存在时应一致 | 结构校验、研究校验 | 保留真实精度，不补造时刻 |
| TIME-002 | 研究与证据 | available_at ≤ as_of ≤ recorded_at；available_at ≤ acquired_at ≤ recorded_at；published_at 非空时 ≤ available_at；日期不替代实际可得时点，明显未来日期拒绝 | 研究校验 | 使用截止时点可得版本 |
| OBS-001 | 观测 value | value=null 必须说明缺失原因；有值必须有证据且 missing_reason=null | 研究校验 | 补证据或登记缺失 |
| OBS-002 | 有效观测 | 指标、分部、单位和时间必须满足登记定义及可得时间要求 | 研究校验 | 核对指标口径和来源版本 |
| CALC-001 | checked 计算 | 必须提供核对证据；参与估值的结果应与情景数量一致 | 研究校验 | 补核对记录或重新计算 |
| FLOW-001 | steps | 固定 S1—S6 顺序；前序未完成不得开展后序；开展步骤必须引用全部前序版本 | 结构校验、研究校验 | 后序保持 pending，先完成前序 |
| FLOW-002 | completed 步骤 | 必须提供完整专用 output，且强制验收项全部 pass | 研究校验 | 补齐输出及验收依据 |
| FLOW-003 | pending 步骤 | output 必须为 null；未完成的输出不能以半截对象提交 | 结构校验、研究校验 | 将过程记录写入 notes |
| VAL-001 | S4 | 必须有 bear/base/bull 三情景；价格引用应为 market_price；每股价值、币种及计算输出应一致 | 研究校验 | 核对情景、价格与计算口径 |
| VAL-002 | 情景概率 | 三项全部 null，或全部提供并合计为 1，且有概率依据 | 研究校验 | 无依据时全部 null |
| DEC-001 | 未评估组合 | position_fraction 必须 null；不能据此生成仓位比例 | 研究校验 | 补组合资料及计算再评估 |
| DEC-002 | 行动条件满足 | 不得由未验证的行业规则或合成资料支持行动条件满足结论 | 研究校验 | 保持观察或无法判断 |
| INV-001 | open 失效事件 | 从 earliest_step 至 S6 连续回退，记录旧版本；未解决时不得保留有效后序完成状态 | 研究校验 | 补齐连续回退范围 |
| INV-002 | resolved 失效事件 | 受影响步骤必须重新完成并高于基线版本，更新依赖和解决时间 | 研究校验 | 完成重研究后再解除失效 |

## 3. 来源与历史治理规则

| 编号 | 适用对象／条件 | 规范要求 | 执行责任 | 失败后的处理 |
|---|---|---|---|---|
| GOV-001 | 资料登记 | 修订按系列连续追加；首版 supersedes_revision=null，后版指向前版；不得覆盖既有修订 | 入库校验 | 登记新修订 |
| GOV-002 | 真实研究入库 | 全部 evidence.id 必须绑定已登记 source_id 与 revision，资料类型、时间和内容必须一致 | 入库校验 | 补来源映射并核对文件 |
| GOV-003 | 研究修订 | 修订连续追加；步骤输入、输出、状态等变化必须增加相关步骤版本 | 入库校验 | 增加修订及步骤版本 |
| GOV-004 | 归档读取与审计 | 固定归档资料、代码和契约；校验内容哈希，异常不得通过改写哈希掩盖 | 读取、审计及备份校验 | 查明差异并核对独立备份 |
| GOV-005 | 历史查询 | 同时遵守信息截止时点及记录形成时点；不能将后来的修订当作当时已知 | 数据目录历史查询 | 调整查询时点和版本 |

## 4. 专业复核与工程提示

| 编号 | 要求 | 执行责任 | 结果含义 |
|---|---|---|---|
| MAN-001 | 原文摘要应忠实，locator 能定位相关内容，同源摘录不得视为独立来源 | 人工复核 | 结构与来源绑定检查不能证明事实真实性 |
| MAN-002 | 分清 GAAP／调整后、合并／分部、单季／TTM、复权与汇率等口径 | 人工复核；部分单位由研究校验检查 | 不能仅凭单位相同认定经济口径可比 |
| MAN-003 | 模型适用性、公式正确性、假设合理性和行业阈值必须有相应研究与验证 | 人工复核及未来计算、校准工具 | checked 是有核对记录的声明，不等于金融模型认证 |
| DQ-001 | 按质量政策检查资料年龄、缺少行业驱动指标及未复核分类 | 数据质量工具，输出提示 | 提示不等于统计阈值，不自动填值或作投资判断 |
