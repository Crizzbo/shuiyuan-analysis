# 财报数据字典与官方三表全息实体契约技术设计规格书 (Financial Report Dictionary & Statements Entity Schema Spec)

> **功能标识**：`FINANCIAL_REPORT_DICTIONARY_SPEC`  
> **所属业务分类**：类别 C：微观公司内在价值与财务估值（官方三表标准科目事实、跨准则映射、会计勾稽平账检验、指标派生与血缘溯源）  
> **技术成熟度**：生产基准 (Production)  
> **单一事实来源**：  
> - 核心契约底账：`schemas/financial-report.schema.json`

## 一、 功能背景与业务用途

### 1. 业务背景
在买方机构针对美股（US-GAAP）、日股（J-GAAP）及跨国企业（IFRS）进行微观财务法证与内在价值建模时，直接将未经结构化标准化的三表数据写入计算引擎，极易引发三大约束失控：一是“会计科目口径混淆”，各准则对研发费用资本化、租赁负债及少数股东权益的处理定义迥异；二是“表间勾稽破损”，利润表净利润与资产负债表未分配利润变动不勾稽、经营现金流与净利润背离严重却未做防伪检验；三是“计算阻断不可追溯”，当财务指标因分母为零或数据缺失无法产出时，缺乏标准化的阻断原因登记机制。本规范确立统一的 10 大核心实体契约模型（`Report`, `Fact`, `Period`, `Source`, `Check`, `Calculation`, `Registration`, `ExecutionRef`, `SourceVersion`, `IndustryObservations`），为全系统官方三表数据治理提供单一事实来源（SSOT）。

### 2. 核心用途
本功能解决全系统三大微观财务数据契约与平账治理问题：
1. **十大核心财务实体全息解耦 (10-Entity Accounting Architecture)**：建立从报告元数据、标准三表事实、期间时点、原文证据到配平自检、派生计算与登记版本的闭环数据字典；
2. **三表间会计勾稽刚性自检 (Accounting Invariant Checks)**：在入库前强制执行资产负债平衡自检（$A \equiv L + E$）及净利润到自由现金流的调节勾稽，误差超出 $0.1\%$ 刚性拦截；
3. **计算阻断与血缘缺失强类型溯源**：指标计算成功时必须输出单位、有限数值、公式与输入引用；阻断时必须输出确切的阻断原因枚举与缺失字段清单，杜绝静默失败。

## 二、 系统架构上下文与依赖关系

### 1. 前置依赖 (Inputs From Upstream)
- `data_sources/official_filings/`：提供经 SHA-256 哈希锁定的 SEC 10-K/10-Q、东证有価証券報告書原始文件。
- `data/taxonomies/manifest.json`：提供离线加载的 XBRL 2.1 US-GAAP 与 IFRS 分类标准。

### 2. 后置消费 (Outputs To Downstream)
- `financial_core/engines/multistage_dcf_engine.py`：消费标准自由现金流与有息负债净额。
- `financial_reporting/excel_dossier_builder.py`：消费标准三表事实，渲染 5-Sheet Excel Sheet 3 官方底稿。

### 2. 核心数学模型推导

1. **资产负债表刚性配平自检方程**：
   $$\text{Discrepancy} = \frac{|\text{val\_total\_assets} - (\text{val\_total\_liabilities} + \text{val\_total\_equity})|}{\max(|\text{val\_total\_assets}|, 1.0)}$$
   判定门禁：$\text{Discrepancy} \le 0.001$（$0.1\%$ 容差）。
2. **净利润到真实自由现金流调节勾稽方程**：
   $$FCF_{\text{true}} = \text{OperatingCashFlow} - \text{Capex}_{\text{maintenance}} - \text{SBC}$$
   其中 $\text{SBC}$（股权激励费用）作为非现金调节项全额扣除，还原真实真金白银。

## 五、 状态机与事实质量分类 (Fact Quality Registry)

### 1. 财务事实与勾稽质量状态空间

| 状态代号 | 英文枚举标识 | 中文状态名称 | 判定特征 | 系统准入规则 |
| :--- | :--- | :--- | :--- | :--- |
| `FCT_01` | `SOURCE_VERIFIED` | 权威官方核验 | 经官方 XBRL 校验，且三表平账自检 100% 配平。| 允许登记入库，驱动核心估值。 |
| `FCT_02` | `CHECK_FAILED` | 平账自检失败 | 资产负债不平衡度超出 $0.1\%$ 容差。 | 严禁进入估值，整表标红报警。 |
| `FCT_03` | `BLOCKED_INPUT` | 缺少必要输入 | 缺少有息负债或资本开支，无法闭环算值。 | 指标置空，记录确切缺失字段。 |
| `FCT_04` | `RESTATEMENT` | 差错重述更正 | 发行人针对历史报表发布 10-K/A 修正公告。 | 新增版本追加，保留历史版本。 |

## 附录：工程实现与边界自查清单 (Engineering Defense Checklist)

- [ ] **资产负债表绝对刚性配平**：$|A - (L + E)| \le 0.1\%$，任何未配平财报严禁作为 `SOURCE_VERIFIED` 登记入库。
- [ ] **计算阻断原因显式记录**：当财务指标派生失败时，`value` 必须置为 `null`，且必须显式给出 `blocked_reason`，严禁填充伪造零值。
- [ ] **货币单位与量纲严格对齐**：日元报表必须区分“百万日元”与“亿日元”，美元报表必须区分“千美元”与“百万美元”，严禁数量级错位。
- [ ] **勾稽检查必须附带输入引用**：每个 `Check` 对象必须携带参与核算的原始科目引用列表 (`inputs`)，确保核验过程可审计。
- [ ] **历史重述必须只追加不手改**：针对官方会计差错更正，必须作为新增版本追加写入数据库，严禁对已登记的权威事实执行 SQL 物理覆盖。
