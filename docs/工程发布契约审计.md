# 工程发布契约审计

在项目根目录运行，使用工程现有的 Python 和依赖。

```powershell
python -X utf8 scripts/audit_project_contracts.py
python -X utf8 scripts/audit_project_contracts.py --group quote --group ledger
python -X utf8 scripts/audit_project_contracts.py --check R01 --check R03
python -X utf8 scripts/audit_project_contracts.py --layer UT --layer CT
python -X utf8 scripts/audit_project_contracts.py --point IT-05
python -X utf8 scripts/audit_project_contracts.py --coverage --json
python -X utf8 scripts/audit_project_contracts.py --json
```

每项给出固定编号、四层分类、[清单测试点](38-水源投研工程四类测试点与验收清单.md)、风险等级、代码位置和实际观察。全部通过时退出码为 `0`。发现契约违反或探针执行异常时退出码为 `1`，其余探针继续执行。覆盖表里的关联表示该点已有直接探针，完整验收仍需按清单检查其余分支。

| 结果 | 含义 |
| --- | --- |
| `PASS` | 当前探针的契约成立 |
| `FAIL` | 探针成功执行，观察到契约违反 |
| `ERROR` | 环境、依赖或意外异常阻止探针得出结论 |

| 编号 | 范围 |
| --- | --- |
| Q、F | 报价时效与市场时段、财报来源与单位、DCF 闭式基准、期权无套利 |
| L | 哈希覆盖、冲突重试、对账结果篡改、正式预测账本副本验签 |
| R、C | 日报负向端到端、试运行副作用、Schema、PDF 渲染回执、工作流调度和参数 |
| B、A | 资产池计数、批处理恢复与并发覆盖、行业别名、依赖方向、本地路径 |
| I | 财报与估值交接、行情门禁、知识图谱边界、预测对账时序 |
| D、X、G、T | 现有档案结构和发布内容、ETF 和黄金输入边界、资料目录治理、隔离自检 |

探针在 `.cache/project-audit-*` 下使用独立临时目录，完成后清理。账本篡改实验使用新建的 SQLite，正式账本只复制后验签。运行时阻止连接网络、启动外部程序和写入临时目录之外的位置。固定日期和合成输入只用于测试。

Windows 环境若拒绝原子替换，`B06` 会单独报告运行错误。`B01` 和 `B02` 在该限制下用隔离文件验证业务状态，因此仍能区分试运行污染和更新覆盖。云端与 PDF 检查覆盖本地控制流和工作流配置，实际 GitHub Actions、浏览器渲染和 Drive 上传需用部署环境验证。

四类探针由 [发布审计入口](../scripts/audit_project_contracts.py) 统一加载，原命令和探针编号继续可用。现有 `unittest discover` 继续执行日常回归，发布审计作为独立门禁暴露生产契约失败。修复生产问题时，先用相关编号复验，再运行完整审计和项目既有四道验收门禁。

按设计书分阶段执行见 [分阶段测试体系与发布门禁](39-水源投研分阶段测试体系与发布门禁.md)。`--coverage` 列出四类测试点和直接探针，`--matrix` 进一步列出设计场景及待补证据。以下场景已有局部离线探针，完整验收仍需要专用数据或部署环境。

| 测试点 | 验收边界 |
| --- | --- |
| FT-04 | 合成档案和五页 Excel 已可回读，正式验收仍需美日两套可复算的完整财报、报价、事件和证据 |
| IT-07 | 离线已核验单批逐件顺序及坏回执，实际异步交付顺序和跨任务续传需在部署环境取证 |
| IT-09 | 离线已覆盖空目标误完成，仍需核验首期缺一项和全量合格的真实扩展触发 |
| IT-10 | 离线已覆盖浏览器回执和原文字节归档，仍需验证真实获准导入后只重算关联档案 |
