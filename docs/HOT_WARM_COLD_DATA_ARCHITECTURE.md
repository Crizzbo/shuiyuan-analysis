# 买方冷热数据分层生命周期与云端防泄露架构说明书

> **设计铁律**：**云端（GitHub 仓库）只放加工、压缩、索引与唤醒数据的工具和方法，绝不放任何实际数据底账！**  
> **适用对象**：本地 3GB+ 原始财报底稿、高频行情时序、每日研报快照及十年极限回测存档。

---

## 一、 核心设计哲学：云端“轻装方法论” × 本地“冷热三层库”

在机构级量化投研中，每日积累的官方财报（单家公司 SEC XBRL 底稿动辄 4~10MB，包含长达 20 年的历史字段）、全市场日线价量与历史回测快照会导致三大痛点：
1. **日常启动慢**：盘前 3 分钟决策只需要看最近 30 天行情与近 1~2 年核心财务，但直接读取全量底稿每次都要解析数万行陈旧数据；
2. **磁盘冗余膨胀**：数千家公司超过 3 年以上的历史底稿占用了本地 80%~90% 的磁盘体积；
3. **误推 GitHub 风险**：海量本地数据文件一旦混入代码提交，会导致远程仓库瞬间瘫痪并违背数据隔离底线。

为此，系统建立**物理边界彻底隔离、数据生命周期自动化流转**的冷热分层架构：
- **GitHub 云端代码库**：仅存储分层调度核心算法、无损时间切片方法、压缩归档脚手架、防泄露物理守卫及全套单元测试；
- **本地工作站数据盘**：全部纳入 `.gitignore` 物理隔离，划分为 **热数据 (`data/hot/`)**、**温数据 (`data/warm/`)**、**冷数据 (`data/cold/`)** 三大专责区域。

---

## 二、 冷热温三层数据边界与业务用途矩阵

| 数据层级 | 时效与年代范围 | 对应商业应用场景 | 本地物理形态与格式 | 读写速度与空间表现 |
| :--- | :--- | :--- | :--- | :--- |
| **🔥 热数据层<br>(Hot Tier)** | • 行情/事件：30 天内<br>• 财报切片：近 1~2 年（近 4~6 季度） | • 盘前 3 分钟行动指南与击球买点判断<br>• 流水线看板实时呼吸灯与消息流转<br>• 实时流动性冲击与期权多空比盯盘 | 极简紧凑单行 JSON (`data/hot/`)，零压缩零解析冗余 | **毫秒级直读**，体积仅占原始财报的 **5% ~ 10%** |
| **🌤️ 温数据层<br>(Warm Tier)** | • 行情/事件：31 天 ~ 3 年<br>• 财报切片：近 3 年（近 12 季度） | • 250 日均线与 VCP 波动收缩初筛<br>• 连续 12 个季度财报杜邦与自由现金流贴现<br>• 轻量索引清单登记 (`manifests/`) | 紧凑单行 JSON (`data/warm/`) + 轻量 SHA-256 指纹索引 | **百毫秒级定位**，体积缩减 **70% ~ 80%** |
| **❄️ 冷数据层<br>(Cold Tier)** | • 行情/财报：3 年以上历史全周期（如 2007~2022） | • 十年跨周期黑天鹅极限压力测试<br>• 历史法证审计与跨年回测按需唤醒 | Gzip 最高级无损压缩归档 (`data/cold/*.cold.json.gz`) | **空间节省 85% ~ 93%**，按需秒级解压唤醒 |

## 三、 无损拆分与防篡改验签机制 (Zero Data Loss)

为了保证任何历史数据在压缩下沉多年后依然可以**100% 精准无损还原**，核心引擎 [data_lifecycle_engine.py](../financial_core/engines/data_lifecycle_engine.py) 采取了刚性的工程安全网：

1. **严格互斥分片契约**：
   - 温数据切片包含基准年近 3 年以来的所有财报事实（以及极少数缺失年份标签的异常条目，保守兜底绝不丢数）；
   - 冷数据切片包含 3 年以前的全部老旧历史财报事实；
   - **温区 + 冷区 = 原文件 100% 全部记录**（零遗漏、零重复），热区则为温区最近 1~2 年的高频速查子集。
2. **双层密码学指纹护航**：
   - 拆分前计算原始底稿顺序无关全集 SHA-256 指纹与精确条目总数，存入轻量清单；
   - 落盘后强制当场从磁盘重新读取温区 JSON 与冷区 `.json.gz`，合并还原并比对条目总数与 SHA-256 指纹，**100% 吻合才允许签发通过**。
   - 任何外部误修改或磁盘损坏哪怕 1 个字节，唤醒工具会立刻报错熔断拦截。

## 四、 云端核心工具箱一览 (全部沉淀于 GitHub)

| 架构层级 | 文件路径 | 核心职能 |
| :--- | :--- | :--- |
| **底层纯净引擎层** | [data_lifecycle_engine.py](../financial_core/engines/data_lifecycle_engine.py) | 零外层依赖的冷热分拣、时间切片、Gzip 压缩还原与防泄露检测核心引擎 |
| **中继门面层** | [data_lifecycle_manager.py](../finance_tools/governance_and_pipeline/data_lifecycle_manager.py) | 遵循四层单向架构铁律的工具层门面导出 |
| **本地批处理 CLI** | [compact_cold_data.py](../scripts/compact_cold_data.py) | 本地单标的打样、全盘批量分层、磁盘状态巡检与秒级唤醒检验工具 |
| **防泄露安全守卫** | [verify_no_data_leak_guard.py](../scripts/verify_no_data_leak_guard.py) | 扫描 Git 暂存区与追踪列表，物理拦截任何数据与压缩归档提交，支持挂载 Git 钩子 |
| **自动化单元测试** | [test_data_lifecycle_engine.py](../scripts/test_data_lifecycle_engine.py) | 覆盖时效分类、互斥拆分、压缩防篡改、云端边界检查的完整单测套件 |

## 五、 标准操作指南 (SOP)

```bash
# 1. 巡检当前本地热/温/冷数据空间分布
python scripts/compact_cold_data.py --status

# 2. 先打样验证单家核心标的（默认安全模式，保留原文件，不破坏现有底账）
python scripts/compact_cold_data.py --sample-ticker NVDA

# 3. 唤醒并校验冷数据压缩包的 100% 无损完整性
python scripts/compact_cold_data.py --restore-check NVDA

# 4. 确认打样无误后，对全盘官方财报执行批量防阻塞冷热加工
python scripts/compact_cold_data.py --batch-sec

# 5. 提交代码至 GitHub 前执行防数据泄露物理门禁检查（或安装为本地永久钩子）
python scripts/verify_no_data_leak_guard.py
python scripts/verify_no_data_leak_guard.py --install-hook
```
