# 每日大盘研报工程化规范与生成程序技术设计规格书 (Daily Briefing Pipeline Specification)

> **功能标识**：`PIPELINE_DAILY_BRIEFING_GENERATOR`  
> **所属业务分类**：类别 E：底层数据工程层面（每日金融大盘研报、Schema 强契约双模渲染与自包含多模态交付）  
> **技术成熟度**：生产基准 (Production)  
> **单一事实来源**：  
> - 构建程序：`scripts/build_daily_briefing.py`  
> - 结构契约：`schemas/daily_briefing.schema.json`（或 `schemas/daily-briefing.schema.json`）  
> - 自动化测试集：`scripts/test_daily_briefing.py`  

---

## 一、 功能背景与业务用途

### 1. 业务背景
在买方机构日常投研实践中，传统早报制作面临四大系统性痛点：一是手工撰写容易出现格式混乱与核心要素遗漏（如宏观贴现率、主力资金流向或风控清单缺失）；二是行情与估值数据手工摘抄易发生口径漂移与抄录笔误，缺乏可验证的底层计算凭据；三是纯文本 Markdown 缺乏机构级视觉表现力，而手工编写 HTML 则存在标签未闭合或引用外部不可控 CDN 的安全隐患；四是根据项目合规要求，早报必须实现 100% 离线自包含，零依赖外部未经授权网络请求。本功能构建基于 JSON Schema 契约驱动、严格语法校验、双模自动化渲染的工业级每日大盘研报生成程序。

### 2. 核心用途
本功能解决三大投研交付工程问题：
1. **Schema 强契约驱动的统一事实源 (SSOT)**：所有宏观脉搏、资金流向、情绪指标与个股推演统一由单一结构化 JSON 文件输入，执行 Draft 2020-12 强类型前置拦截；
2. **Markdown 与暗色自包含 HTML 双模同步渲染**：同一数据源同步编译出符合 GitHub 渲染规范的 Markdown 归档文件，以及内嵌专业 CSS 样式与响应式布局的暗色 HTML 终端仪表盘；
3. **宏观决策与个股进攻防守池穿透**：通过结构化卡片明确战术配置姿态（硬性现金底线、标普 ERP）、精选进攻买点与防守避险池，杜绝无意义机械打印全量大表。

## 二、 系统架构上下文与依赖关系

### 1. 前置依赖 (Inputs From Upstream)
- `data/briefings/{DATE}/briefing_input.json`：提供包含宏观、行业、情绪与标的推荐的标准输入事实。
- `schemas/daily_briefing.schema.json`：提供 JSON Schema 语法与字段约束定义。

### 2. 后置消费 (Outputs To Downstream)
- `data/briefings/{DATE}/daily_briefing.md`：知识库版本控制与终端文本阅读归档。
- `data/briefings/{DATE}/daily_briefing.html`：本地浏览器交互式决策看板与矢量呈现。

### 2. 核心数学模型推导

1. **股权风险溢价 (Equity Risk Premium, ERP)**：
   $$ERP = \frac{1}{\text{P/E}_{\text{SP500}}} - Y_{10Y\_Treasury}$$
   约束判定：当 $ERP \le 0.50\%$ 时，指示美股估值处于极度泡沫化高位，必须强制提升硬性现金比例至 $75\%$ 以上。
2. **市场情绪综合加权得分**：
   $$\text{Sentiment Score} = w_1 S_{\text{vix}} + w_2 S_{\text{pcr}} + w_3 S_{\text{breadth}} + w_4 S_{\text{safe\_haven}}$$
   得分范围严格归一化至 $[0.0, 100.0]$。
3. **复利年化安全收益率测算**：
   $$R_{\text{cash}} = (1 + r_{\text{tbill}})^{\frac{D}{365}} - 1$$

## 附录：工程实现与边界自查清单 (Engineering Defense Checklist)

- [ ] **Schema-First 绝对前置断言**：在进入任何字符串拼接与 HTML 模板渲染前，必须执行 `Draft202012Validator.validate()`，遇错即阻断。
- [ ] **自包含零外链约束**：生产的 `daily_briefing.html` 必须内联所有 CSS 样式表与字体声明，严禁在 HTML 中引入外部第三方 CDN 脚本与样式链接。
- [ ] **双模一致性保障**：Markdown 报告与 HTML 仪表盘必须由同一个 Python 进程、同一份 JSON 输入派生，严禁两份输出存在事实或数字偏差。
- [ ] **日期格式正则校验**：日期输入必须满足严格正则 `^\d{4}-\d{2}-\d{2}$`，严禁不合法的时间戳字符串通过校验。
