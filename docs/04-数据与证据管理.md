# 数据与证据管理系统技术设计规格书 (Evidence Governance & Data Store Specification)

> **功能标识**：`DATA_GOVERNANCE_EVIDENCE_STORE`  
> **所属业务分类**：类别 E：底层数据工程层面（不可变证据治理、只追加台账、SHA-256 哈希对象存储与审计回溯）  
> **技术成熟度**：生产基准 (Production)  
> **单一事实来源**：  
> - 底层存储引擎：`scripts/data_store.py` (`DataStore`)  
> - 命令行操作门面：`scripts/data_catalog.py`  
> - 质量评估中枢：`scripts/data_quality.py`  
> - 元数据契约规范：`schemas/source-manifest.schema.json`  
> - 自动化测试集：`scripts/test_data_store.py`

## 一、 功能背景与业务用途

### 1. 业务背景
在买方机构研究与量化决策系统中，证据与原始数据的真实性、可追溯性是支撑投资决策的基石。传统数据存储常存在三大缺陷：一是缺乏不可变性，数据库中的历史数据可被随意更新覆盖，导致历史研报失去当时的事实依据；二是证据时间戳混乱（如混淆发布时间、可得时间与采集时间），发生“利用后验数据测算历史预测”的前瞻性偏差；三是缺乏密码学校验，无法检验文件是否遭受物理损坏或人为篡改。本功能构建不可变、只追加、基于内容哈希寻址（Content-Addressed Storage）的买方证据治理底账系统。

### 2. 核心用途
本功能解决三大证据治理工程问题：
1. **只追加（Append-Only）物理存储与防覆盖触发器**：SQLite 底账内置触发器，禁止执行任何 SQL `UPDATE` 或 `DELETE` 语句，历史事实永久只读保留；
2. **SHA-256 内容寻址对象存储 (`.blob`)**：原始文件依据内容哈希唯一命名并存入 `data/catalog/objects/`，实现跨来源文件去重与完整性自校验；
3. **时点回溯与时间契约分离 (Point-in-Time Separation)**：严格区分发布时间（published_at）、可得时间（available_at）与采集时间（acquired_at），支持精确回放历史任意截面的可用信息。

## 二、 系统架构上下文与依赖关系

### 1. 前置依赖 (Inputs From Upstream)
- `data_sources/` 与官方采集文件：提供未经修改的原始 PDF、XBRL、JSON 底稿。
- `schemas/source-manifest.schema.json`：提供资料元数据登记强契约。

### 2. 后置消费 (Outputs To Downstream)
- `financial_core/engines/official_filing_mapper.py`：消费经哈希锁定的官方财报底账。
- `scripts/validate_research.py`：消费来源映射关系，执行六步研究证据闭环核验。

### 3. 数据流转时序图
```
┌──────────────────────────────────────┐
│  原始财报底稿与元数据清单 (manifest)  │
└──────────────────┬───────────────────┘
                   │ (SHA-256 计算与 Schema 校验)
                   ▼
┌──────────────────────────────────────┐
│  数据与证据治理存储底座 (DataStore)  │
│  ├── 写入 objects/{hash}.blob 对象   │
│  ├── 登记 catalog.sqlite3 (只追加)   │
│  └── 触发器拦截任何 UPDATE / DELETE  │
└──────────────────┬───────────────────┘
                   │ (不可变证据引用句柄)
                   ▼
┌──────────────────────────────────────┐
│  历史时点研究回放与审计对账          │
│  (as_of 时间截面查询与防篡改扫描)   │
└──────────────────────────────────────┘
```

### 2. 核心数学模型推导

1. **SHA-256 密码学生成方程**：
   $$\text{Digest} = \text{SHA-256}(\text{RawBytes})$$
   对存储对象实施字节级完整性校验，若读取时的字节流哈希与登记摘要不符，立即抛出 `BlobIntegrityCorruptedError`。
2. **时间契约偏序关系刚性断言**：
   $$\text{published\_at} \le \text{available\_at} \le \text{acquired\_at}$$
   若任意环节发生时间倒挂，系统拒绝登记并终止事务。
3. **时点回溯查询条件**：
   $$\text{ActiveRevision} = \arg\max_{r} \Big( r.\text{revision} \;\Big|\; r.\text{available\_at} \le t_{\text{as\_of}} \land r.\text{recorded\_at} \le t_{\text{as\_of}} \Big)$$

## 五、 状态机与证据生命周期 (State Registry)

### 1. 证据登记与版本生命周期状态空间

| 状态代号 | 英文枚举标识 | 中文状态名称 | 判定条件 | 存储动作 |
| :--- | :--- | :--- | :--- | :--- |
| `EVD_01` | `REGISTERED` | 原始登记完成 | 字节写入 .blob 且元数据录入成功。 | 处于只读激活状态。 |
| `EVD_02` | `SUPERSEDED` | 已被新版替代 | 发行人发布财报重述，追加新版本。 | 标记旧版被替代，保留历史。 |
| `EVD_03` | `TAMPER_LOCKED`| 篡改破坏锁定 | 物理文件哈希与数据库登记不匹配。 | 锁定该证据，阻断一切下游引用。|
| `EVD_04` | `SYNTHETIC_DEMO`| 合成演示标记 | 属于测试样例，未关联真实官方底稿。| 仅供研发测试，严禁用于实盘。 |

## 六、 返回值与输出数据结构 (Output Contracts)

资料登记执行完毕后，统一产出凭据字典：

```json
{
  "source_id": "sec_filing_nvda_20261014",
  "revision": 1,
  "sha256": "4a7b8c9d...64位十六进制",
  "storage_path": "data/catalog/objects/4a7b8c9d...blob",
  "locator": "data_sources/official_filings/sec/nvda_10k_2026.json",
  "timestamps": {
    "published_at": "2026-10-14T10:00:00Z",
    "available_at": "2026-10-14T10:05:00Z",
    "acquired_at": "2026-10-14T10:15:00Z"
  },
  "is_idempotent": false,
  "audit_status": "VERIFIED_PASS"
}
```

### 输出字段逐项业务释义
| 输出字段名称 | 字段标识 | 数据类型 | 计量单位 | 业务释义 |
| :--- | :--- | :---: | :---: | :--- |
| 资料系列代码 | `source_id` | `str` | 字符串 | 资料系列的唯一业务代号。 |
| 修订版本号 | `revision` | `int` | 整数 | 从 1 开始严格递增的版本序号。 |
| 密码学摘要 | `sha256` | `str` | 64字符十六进制 | 原始文件字节流的 SHA-256 唯一数字指纹。 |
| 物理存储路径 | `storage_path` | `str` | 相对文件路径 | 原始数据在对象库中的具体物理存放位置。 |
| 幂等重复提交 | `is_idempotent` | `bool` | 布尔值 | 指示本次登记是否为相同内容的合规重复提交。 |

## 附录：工程实现与边界自查清单 (Engineering Defense Checklist)

- [ ] **数据库禁止修改触发器**：SQLite 底账关键表必须配置 `CREATE TRIGGER ... BEFORE UPDATE ... RAISE(ABORT)` 与 `BEFORE DELETE`，杜绝任何历史事实篡改。
- [ ] **路径越界与绝对路径阻断**：所有入库路径必须解析为项目根目录内的相对路径，严禁使用包含盘符的绝对路径、UNC 路径或 `../` 越界路径。
- [ ] **时间契约偏序单调性断言**：必须满足 $\text{published\_at} \le \text{available\_at} \le \text{acquired\_at}$，严禁未来时间倒流。
- [ ] **研究入库契约全量封存**：保存研究时必须将当前所用的 Schema、指标定义及计算代码完整拷贝封存至修订目录，杜绝字典后续演进破坏历史研究的可复核性。
