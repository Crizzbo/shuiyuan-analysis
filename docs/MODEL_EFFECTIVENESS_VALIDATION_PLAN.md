# 金融模型效果验证方案（设计稿）

## 1. 目标与当前边界

本方案针对本项目的 DCF / Monte Carlo、SOTP 事件穿透、期权、组合风险、信用风险和信号模型，检验三件不同的事：计算是否正确、预测是否有效、使用后是否改善决策。

本文件是待实施的实验设计，不代表已经完成回测、统计校准或取得超额收益。全部实验只使用项目内可追溯资料；合成数据只验证实现，不能进入真实效果统计。没有历史样本时状态为 `INSUFFICIENT_EVIDENCE`，不启用数值效果门槛。

现有接入点：

- [工程质量门禁](SPEC_12_系统质量工程密码学账本与全息测试验收标准.md)：验证代码与数据治理。
- [预测账本](../financial_core/engines/prediction_ledger.py)：保存预测、结果和复盘并验签。
- [复盘引擎](../financial_core/engines/retrospective_review_engine.py)：已有目标价格、结果价格和归因结构。
- [SOTP 档案契约](../schemas/sotp_profiles.schema.json)：区分本地事实、来源与未校准假设。

现有复盘中的价格走廊、单个结果价格和文字解释，不自动等于预测区间校准、交易路径回测或因果识别。当前方案不改动它们，也不修改其他 agent 正在维护的行情和雷达模块。

## 2. 五层检验，逐层形成结论

| 层级 | 要回答的问题 | 证据与方法 | 可形成的结论 |
|---|---|---|---|
| A：计算正确性 | 公式实现是否正确？ | 独立参考值、解析特例、边界、单位与币种一致性、收敛检验 | 计算通过，不代表预测有效 |
| B：经济合理性 | 输入变化时输出是否合理？ | 条件敏感性、极端情景、资产负债平账、无套利约束 | 结构合理，不代表参数已校准 |
| C：样本外预测 | 未见过的历史时期是否优于简单方法？ | 时间滚动、冻结输入、盲测、误差与校准比较 | 对限定对象和期限有或无预测证据 |
| D：决策价值 | 实际可执行后是否仍有用？ | 费用、成交、流动性、仓位和风险匹配的策略回测 | 限定规则下的历史决策证据 |
| E：前瞻影子运行 | 新数据持续进入后是否仍可靠？ | 发布前存证、到期自动评估、持续记录失败与弃权 | 前瞻稳定性证据 |

各层分别出状态，不能用“全部单测通过”替代 C～E 层。模型可以在某行业有效、另一个行业证据不足，禁止只给全局一个通过标志。

## 3. 每个实验先冻结一份实验卡

每次实验使用唯一 experiment_id，必须在看测试结果前固定以下字段：

1. 模型名称、代码提交、工作区补丁摘要、依赖锁文件摘要、参数版本和随机种子；工作区非干净时显式标记，不能只记录 commit。
2. 研究问题、适用市场/行业/资产类别、预测对象、期限、单位、币种、总回报或价格回报口径。
3. 样本池形成规则、训练/验证/最终测试日期、数据可用时间规则、标签成熟时间、缺失与退市处理。
4. 简单基准、主指标、辅助指标、经济意义容忍带、区间估计方法、多重比较处理。
5. 交易规则（如适用）、交易费用、滑点、成交时点、仓位限制、无法成交与弃权处理。
6. 停止条件、失败条件、数据排除规则、最终测试解封条件与复核责任。

效果阈值和样本需求先依据试点数据的相关结构、指标方差与业务容忍度制定，再冻结到实验卡；不能看完最终测试后修改。若试点资料不足，保留定性状态。

## 4. 历史样本的最低数据契约

每条预测保存：prediction_id、experiment_id、模型/参数版本、标的永久标识、预测生成时间（含时区）、信息截止时间、目标期限、预测值或分布、弃权原因，以及全部输入的相对路径和 SHA-256。

每份事实至少保存：观察期、原始发布时间、项目归档时间、修订版本、来源定位、数值/单位/币种、official/synthetic 标识。公司财报的期末日不等于公布日；宏观数据必须使用当时已公布的版本。

历史回放分开记录 `simulation_as_of` 与今天的真实运行时间。历史时效门禁按回放时钟核验，不以今天的行情替代过去，也不更改实时行情门禁来让旧数据通过。

每条结果保存：标签定义、窗口起止、结果来源与摘要、成熟状态、调整规则。结果未到期标为 `PENDING_MATURITY`，缺结果标为缺失，不记为成功或零收益。

关键防偏差规则：

- 使用当时可知的资产池，保留退市、破产、并购和停牌主体。只有今天仍存续的公司时，明确存在幸存者偏差。
- 发布前生成不了的输入不得回填；今天采集的旧文件即使带旧日期，也不能自动证明历史系统当时可用。
- 拆股和分红采用一致的价格/总回报口径，防止未来公司行动泄漏；US 与 JP 分市场评估，跨币种回报显式处理汇率。
- 搜索摘要、AI 补写数字、人工挑选的成功案例、测试夹具不能作为真实标签。
- 每轮输出总候选数、数据可用数、预测数、弃权数、成熟数、缺结果数和排除原因，防止只统计容易预测的样本。

## 5. 不同模型分别检验什么

| 模型与项目模块 | 优先检验目标 | 简单基准 | 主要评价与边界 |
|---|---|---|---|
| 三表、DCF、Monte Carlo：integrated_three_statement_engine / firm_value_added_bridge_engine / monte_carlo_engine | 收入、利润率、FCF 等驱动量及其预测分布 | 上期值延续、历史中位利润率；同一时点可获得的简单估值 | MAE、中位绝对误差、按训练期尺度归一化误差；有明确概率分布时才测区间覆盖和区间宽度/评分。内在价值没有直接可观测真值，后续股价仅作辅助证据 |
| SOTP：event_radar/sotp_event_penetration_engine | 事件后的分部收入/EBIT变化及传导方向 | 无冲击；不区分分部的简单冲击 | 分部误差、方向、相对基准改进、假设敏感性。披露不足则不能评分；混杂事件与公司调整要标注，不能把相关当因果 |
| 期权：american_option_tree_engine / volatility_surface_engine / options_causal_analyzer | 价格、风险敏感度、对冲误差 | 冻结的简单波动率定价；匹配行权结构的参考实现 | 报价同步性、相对买卖价差的定价误差、对冲损益扣费；欧式/美式、分红与提前行权分开。风险中性概率不能当真实上涨概率 |
| 组合风险：portfolio_risk_engine | 下一窗口损失分布和尾部风险 | 只用过去数据的历史模拟、固定的简单波动率模型 | VaR 超越频率与聚集、ES 尾部损失联合诊断、区间不确定性和压力损失；极端样本不足不能宣称尾部有效 |
| 信用：credit_risk_engine | 固定期限真实违约与损失 | 同期行业/评级基准（必须有本地历史资料） | 有真实概率含义时测 Brier/对数损失、校准及排序；违约与删失口径固定。结构模型指标/风险中性概率不得直接充当经验违约率 |
| 买点/选股：sepa_buy_signal_engine 等 | 固定期限收益排序与可执行组合 | 同资产池等权、市场基准、规则复杂度较低的固定信号 | 截面秩相关、扣费超额收益、回撤、换手、暴露与容量；不以胜率单独判优 |
| 宏观与因果模块 | 预先定义的变量变化、预测增量或可识别的处理效应 | 持续值、无冲击、去掉传导模块 | 预测误差与消融；缺识别条件时只称情景分析，不宣称识别因果效应 |

三态悲观/中性/乐观不是天然的概率分位数。没有事前定义概率与期限时，不计算“80% 区间覆盖”，也不把价格落在宽走廊里当成功。

A/B 层另需满足：固定适用条件下折现率敏感性、WACC 与永续增长边界、负现金流/困境场景、极低股本、期权无套利、波动率曲面约束、随机模拟多种子与采样收敛。单调性只能在其假设成立时断言。

## 6. 时间滚动与最终盲测

1. 先做数据盘点，确认每种模型可用的历史跨度、行业数、独立事件数、违约数及结果成熟情况。记录缺口，不预设已经拥有完整历史数据。
2. 按时间顺序分训练、验证和最终测试，禁止随机打散造成未来信息进入过去。训练窗口内拟合参数；验证窗口选规则；最终测试只评价已冻结版本。
3. 每个滚动起点只用此前可用且标签已成熟的样本；对重叠预测窗口剔除跨边界标签并设置相应间隔。截面共享冲击和同公司重复样本不能当独立观测。
4. 最终测试由预先指定的复核机制解封。测试结果用于下一轮改进后，该时段就成为开发资料；下一轮需要新盲测或前瞻样本。
5. 分别报告市场、行业、规模、流动性、不同市场状态的效果。市场状态划分规则也必须事前冻结，不能事后只展示有利分组。

历史输入由 AI 解释时，模型可能已从训练资料知道后续事件。此类历史叙事结果只能视为辅助分析，不能凭“提示只看当时资料”宣称无前视偏差；优先用确定性计算回放，并以真实前瞻影子运行检验 AI 决策部分。

## 7. 统计证据与经济价值分开报告

- 同一预测样本上比较模型与基准的误差差值，既报告效果大小，也报告不确定区间。
- 时间相关采用时间块重采样；事件研究按事件/发行主体聚类或采用能保持依赖结构的方法。区块长度、聚类层级及方法先写入实验卡。
- 记录所有尝试过的参数、模型与分组，处理多重试验；不能从大量版本中挑出一个好结果后只报告它。
- 不设通用“胜率超过某值就上线”。通过依据是：预注册主指标、业务意义、基准比较、相关性调整后的不确定性，以及风险/覆盖约束共同满足。
- 同时报告缺失和弃权的分布，模型间比较需给出共同样本结果与各自覆盖率，避免通过拒绝困难样本制造优势。

## 8. 交易层检验必须可执行

只有明确交易规则的模型才进入交易绩效评价。信号在信息可用后产生，下单使用之后实际可成交时点；不能用收盘后财报生成信号再按该日收盘价买入。

逐步加入佣金、买卖价差、滑点、冲击、借券可用性/费用、停牌、价格限制、税费与外汇。未取得本地证据的成本参数明确标为假设，做敏感性分析，不能声称真实可成交收益。

对比基准需一致资本、持有期、敞口约束和收益口径；同时展示毛收益、净收益、市场/行业暴露、最大回撤、换手与成交失败。单个期末价不能证明期间触发过买点、止损或目标价。

## 9. 消融、反例与压力测试

- SOTP：完整模型对比去掉分部暴露、库存缓冲、转嫁能力的版本；模型效果应来自明确的信息增量。
- DCF：完整模型对比简单现金流延续；检查结果是否主要由终值或个别主观参数决定。
- 事件：与无事件基准比较；置换/安慰剂保留市场及时间依赖，仅作诊断，不能代替识别设计。
- 风险：测试波动跃升、相关性趋同、流动性消失和跳跃损失；合成危机压力通过只能证明防御行为，不能证明真实危机已校准。
- 数据：重复、缺失、修订、币种错配、陈旧报价和来源摘要不符，应被拒绝或显式降级，不能静默补成“成功”。

## 10. 结果分级与上线边界

每个“模型版本 × 市场/行业 × 预测目标 × 期限”输出独立验证卡：

| 状态 | 含义与使用范围 |
|---|---|
| ENGINEERING_ONLY | 只有实现/边界测试，可做演示和计算辅助 |
| INSUFFICIENT_EVIDENCE | 历史输入、标签或独立样本不足，不给有效性结论 |
| VALIDATION_FAILED | 数据泄漏、基准比较或预注册条件不满足；记录失败，不能悄悄丢弃 |
| HISTORICAL_SUPPORT | 冻结版本取得限定范围的样本外支持，继续前瞻观察 |
| FORWARD_SUPPORT | 已有到期、真实前瞻记录支持，仍按适用范围和风险限制使用 |

每张卡展示数据区间、候选/覆盖/成熟数、独立样本说明、模型与基准指标、不确定区间、成本假设、最大失败案例、已知限制、复现实验摘要。前瞻结果漂移后可降级，不能永久保留通过状态。

## 11. 账本与证据强度

实验输入、预测、结果和复核均采用只追加记录，并由 PredictionLedger 承接预测与结果关联；运行前后执行 `ledger.verify_integrity()`。模型专属字段超过现有结构时，先设计兼容扩展，不能随意塞进评级/文字字段或改写历史记录。

SHA-256 自洽只能证明相对于已知链头的完整性，不能独立证明预测在事件前产生，也不能阻止整条链被重建。前瞻验证需保留独立、可核对时间的链头见证或发布记录；本方案不自动向外发布任何资料。缺少见证时如实标注证据强度。

## 12. 建议实施顺序与协作边界

第一阶段：先完成只读样本盘点和实验卡模板，输出按模型分类的数据缺口。优先选 DCF 驱动量预测、SOTP 分部冲击和组合风险三个试点，确认有合格本地样本后再定实验规模。

第二阶段：建设确定性离线回放、基准和指标模块，先用合成数据证明指标实现正确，再对真实样本出效果报告；两种报告分开。时间切分、标签生成与模型实现由不同复核角色交叉检查。

第三阶段：冻结版本，追加记录真实前瞻预测；到期按统一口径评估，未成熟期间不发布通过结论。先运行影子模式，实际部署另行决策。

建议新实现限定在 financial_core 的独立评估模块（纯本地输入）、scripts 的回放调度和 schemas 的验证契约；不在底层导入外层工具。采集 agent 负责可用时间和证据元数据，模型开发负责输入输出及假设，验证复核负责切分、基准、解封和失败记录；暂不指定 GitHub 合并权限。

本次仅新增设计文档，未实现回测器、未下载数据、未改账本、未进行模型效果评级。后续代码实现仍需依次通过项目的全部架构、单元、治理与账本门禁。
