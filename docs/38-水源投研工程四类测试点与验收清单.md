# 水源投研工程四类测试点与验收清单

审查基线为 `9545fd2`。本文是文字测试设计，表中的预期描述应达到的行为，执行结果以实际验收记录为准。原有用例清单见 [34-系统全量测试用例清单与四层测试方法全景说明书](34-系统全量测试用例清单与四层测试方法全景说明书.md)。

## 分类和执行口径

| 类别 | 验收边界 | 典型证据 |
| --- | --- | --- |
| 单元测试 UT | 一个函数、公式或规则，在固定输入下校验输出和异常 | 输入值、公式基准、异常类型、返回字段 |
| 功能测试 FT | 从用户实际使用的 CLI 或工作流入口触发，检查业务结果和失败行为 | 退出码、研报、文件内容、收据、阻断原因 |
| 单体测试 CT | 隔离运行一个完整子系统，保留其内部真实逻辑和存储，替换对外接口 | SQLite 记录、状态迁移、文件哈希、边界调用记录 |
| 结合测试 IT | 两个及以上真实模块按正式契约交接，检查同一笔数据从输入到交付的完整性 | 来源 ID、报告摘要、账本哈希、任务 ID、远端收据 |

本清单将“单元”和“单体”分开。前者测单函数，后者测完整子系统。本文的“结合测试”即跨模块集成测试。编号在复验和缺陷记录中保持稳定。

- **P0** 用于可能错误发布、污染底账、篡改漏检或改变估值结论的缺陷。出现失败时阻断对应发布链路。
- **P1** 用于兼容性、调度、恢复、可用性和交付质量。执行记录需区分业务失败、环境阻塞和未执行。
- 本地执行使用项目内归档或合成夹具，冻结核验时钟，在隔离目录写报告、状态和 SQLite。正式账本只读取副本。需要浏览器渲染或云端交付的用例使用明确隔离的验收环境和获准来源。
- 写入类负向用例同时比较运行前后的报告目录、进度状态和账本行数。错误码正确但留下正式产物，仍判失败。

## 一、单元测试 UT

| 编号 | 测试点 | 前置条件与动作 | 预期结果 |
| --- | --- | --- | --- |
| UT-01 · P0 | 行情时间戳与价格定义域 | 依次传入缺时区、日期缺时分、未来时间戳、非有限值、零价和负价 | 非法输入被明确拒绝，不以当前时钟补写成交时间。每类输入可识别具体拒绝原因 |
| UT-02 · P0 | 行情交易日归属 | 用同一时刻的 EDT、EST、JST、UTC 表达比较结果。覆盖纽约盘后跨 UTC 零点、DST 切换和交易所本地换日 | 相同观测时刻判定一致。当日归属取市场本地交易日，盘后与前收盘状态不混淆 |
| UT-03 · P0 | 交易时段边界 | 输入美股盘前、开盘、收盘和盘后边界，日股午休、周末、交易所假日和提前收盘夹具 | 核验结果符合相应市场和交易日历。休市及午休观测不能被标成常规盘中最新 |
| UT-04 · P0 | 前收盘与旧盘中报价 | 用最新正式收盘、同日较早盘中报价、上个时段的延迟报价分别核验。周末和长假单独测 | 明确区分当日最新、延迟、最近有效收盘基准、过期阻断。任何降级都保留原始观测时间 |
| UT-05 · P0 | 财务值、币种和量纲 | 对等输入元、百万、亿、带千分位、括号负数和日文金额。覆盖显式总债务、股本、EPS 和现金 | 各口径转换成一致的经济量，币种不串用，显式总债务只缩放一次。缺失值、零值、未知单位分别处理 |
| UT-06 · P0 | 会计恒等式与容差 | 传入恰好平账、容差边界内外、负权益、缺失单项、NaN 和无穷。对比各入口的相同输入 | 容差口径一致，非有限值被拒绝。缺项推导可追溯并单独标注，推导结果不可作为三项均来自披露的证据 |
| UT-07 · P0 | 经营指标与缺项 | 用库存期初期末、销货成本、财期天数验证 DIO。覆盖成本为零、无存货行业、现金与债务缺失 | 结果能按输入复算。分母不可用时保留缺失原因，现金、库存和 DIO 不用固定比例或固定天数冒充披露 |
| UT-08 · P0 | DCF 闭式基准与边界 | 对恒定现金流用 1、5、20 年显式期复算永续公式。覆盖增长率等于或超过折现率、股份为零、FCFE 重扣债务 | 对等模型结果相同，非法终值条件被拒绝。FCFF 与 FCFE 桥接正确，有限责任下界和困境估值状态按模型契约处理 |
| UT-09 · P0 | 期权无套利与极限 | 用可独立复算的期权价格反解波动率。覆盖零到期、极低和极高波动、套利上下界、看涨看跌平价、波动率曲面边界 | 可行域内正反定价一致。越界输入被拒绝或明确标记，曲面违反 Durrleman 或 Roger Lee 约束时有对应结果 |
| UT-10 · P1 | 风险参数与统计校准 | 对照上涨和下跌冲击，输入不足样本、退化协方差、极端尾部和固定随机种子 | 非线性风险在下行场景有可解释变化。样本不足时只输出定性状态，固定种子复算一致 |
| UT-11 · P1 | ETF 与黄金输入边界 | 检查 ETF 重叠率的对称性、空交集、权重和超过 100%、非有限值。黄金输入零、负数和非有限现货值 | 合法 ETF 重叠率在 0% 至 100% 内。坏权重及非法黄金输入明确拒绝。实际利率与溢价使用各自单位 |
| UT-12 · P0 | 本地引用与日期输入 | 对财报路径和报表输出参数传入绝对路径、UNC、URI、编码越界、符号链接越界、非法日期和路径片段 | 在打开或写文件前拒绝越界输入。可解析的项目内相对路径和合法交易日正常处理 |
| UT-13 · P0 | 账本摘要与返回语义 | 对同一预测逐个修改价格、事件、行动、币种、引用及对账字段。对失败结果调用方检查实际分支 | 纳入承诺的字段变化可被发现。验签使用明确的有效位，失败结果无法走成功分支 |
| UT-14 · P1 | 行业归一与身份键 | 输入正式行业 ID、旧别名 `tech_semi`、含糊行业名称、同名或同代码跨市场主体 | 旧别名稳定映射，含糊名称进入待确认。市场和证券身份参与索引，避免跨市场合并 |

## 二、功能测试 FT

| 编号 | 测试点 | 前置条件与动作 | 预期结果 |
| --- | --- | --- | --- |
| FT-01 · P0 | 美股及日股日报正常发布 | 分别用冻结的完整市场快照生成日报 | 两市场按各自交易日输出。宏观、恐慌度、资金流、期权大单与 PCR、新闻、AI 研判可定位到输入。推荐以独立卡片呈现，包含三态触发和买点 |
| FT-02 · P0 | 历史日报冒充当日 | 将固定历史样本提交给相隔多日的正式日报入口。再用第一张新鲜、第二张过期的混合输入运行 | 逐卡核验。日期不被覆盖成当天。被阻断的卡片或整期研报无正式发布和预测记录，降级范围、理由可查 |
| FT-03 · P0 | 日报与建档试运行 | 运行各入口的 dry run，再执行相同参数的正式任务 | 试运行只产生预览信息，不占用正式产物、账本和完成状态。随后正式任务仍可执行 |
| FT-04 · P0 | 公司深度档案正常建档 | 使用项目内可追溯的美股和日股三表、行情、事件与行业证据分别建档 | 档案可追溯到披露财期和科目。净现金、利息红利、库存、供应商客户集中度和护城河有出处。长短期 DCF 情景可复算，评级与估值走廊可解释 |
| FT-05 · P0 | 资料不足及预期冲突 | 移除三表关键项或报价时间戳，构造负安全边际却给出买入评级的输入 | 缺项进入待补数或有明确范围的降级状态。估值与评级冲突被发布门禁拦截，无法仅靠 Schema 通过 |
| FT-06 · P1 | HTML、PDF、Excel 交付 | 用中日文公司名、长事件文本、空字段和含 HTML 特殊字符的合法证据生成报告，解析实际文件 | 内容完整、转义正确、PDF 分页无截断。工作簿页签、单位、公式及引用可核验。失败渲染不得沿用旧 PDF 并登记本次成功 |
| FT-07 · P1 | 投委会简报入口 | 从正常入口用一份通过契约的日报生成完整交付包 | 依赖可加载，纪要内容非空。任何必需产物失败均有明确状态，半成品不会被作为完整包交付 |
| FT-08 · P0 | 六步研究发布 | 用一份完整证据和一份含未来才发布证据的研究分别运行校验及归档 | 完整研究通过各步契约。未来证据、越界引用和非法状态跳转被拒绝。修订按版本追加，可查询旧版本 |
| FT-09 · P1 | 首期和万家覆盖看板 | 用有明确版本的目标清单运行覆盖统计。加入失败、重复、跨市场同代码和已本地未上传项目 | 独立展示目标、具备证据、已建档、已审核、已上传和失败数。零目标不能显示几百家完成，监管索引不计作已研究 |
| FT-10 · P1 | 多资产独立档案 | 走正式 ETF、黄金和成长股入口，分别传入完整证据和仅有静态快照的样本 | 各资产使用适用的契约。ETF 报告可追溯成分及费率日期，黄金报告可追溯实际利率与溢价。静态样本保留观测日期及适用范围 |
| FT-11 · P1 | 云端时钟与手动入参 | 回放 JST 07:00、16:00 两个触发及休市日。手动传入合法日期、空日期和含 shell 元字符的字符串 | 两次任务各跑对应市场，交易日和时区明确。非法参数被拒绝，不能成为 shell 指令或输出路径 |
| FT-12 · P1 | 补数工作单 | 同批制造缺财报、缺行情、缺时间戳和来源不合规，重复执行两次 | 每项记录市场、标的、缺失字段、来源要求和状态。重复任务去重。只生成补数工作单时不能写成已通过浏览器核验 |

## 三、单体测试 CT

| 编号 | 测试点 | 前置条件与动作 | 预期结果 |
| --- | --- | --- | --- |
| CT-01 · P0 | 行情归档读取子系统 | 放入文件名顺序与观测时间相反的多个快照，包括更新但无成交时间戳、过期、币种错误和正确快照 | 返回标的、币种、来源和观测时间匹配的有效快照。采集时间不会充当成交时间，拦截结果不会被覆盖为有效 |
| CT-02 · P0 | 财报标准化子系统 | 同时放入同科目多财期、不同会计口径和修订版本。再输入 SEC、日股及缺项样本 | 选择相同财期与同一口径的三表。保留原文引用、单位、披露时间及修订关系，缺项不混用其他财期或经验数字 |
| CT-03 · P0 | 本地资料目录子系统 | 登记来源、附证据、创建两个研究修订后做备份与恢复，再修改归档字节或历史元数据 | 原有版本可按时点查询，修改能被拒绝或审计发现。恢复库的内容哈希、引用及修订链与备份一致 |
| CT-04 · P0 | PredictionLedger 子系统 | 在临时 SQLite 写预测、实际结果和复盘。重提相同 ID 的相同或不同载荷，修改历史数据，再模拟两个写入者 | 相同载荷幂等。冲突载荷被拒绝或产生可区分修订。并发追加保持链连续，预测、对账和复盘的受保护字段均可核验 |
| CT-05 · P0 | 批处理状态机 | 对同一状态快照交错提交两个标的，模拟进程在产物生成前后中断，然后恢复 | 无进度覆盖。已持久化且可校验的任务可跳过，部分完成任务可重试。失败、试运行、本地完成和远端完成独立记录 |
| CT-06 · P1 | 批处理大规模与增量 | 用固定合成资产池按 50 至 100 家分块。注入单项失败、批失败、外部限速、版本变化和重启 | 并发不重领同一工作项。错误可定位到市场、标的及输入版本。新证据只触发受影响项重算，记录吞吐和失败率 |
| CT-07 · P0 | 深度档案合成子系统 | 注入有效证据和恶意或矛盾的 AI 文本。包括编造数值、宣称引用缺失原文、沿用历史评级 | 报告中的定量事实能追溯到归档或可重算模型。未经证据支持的声明降级或拦截，模型推断有独立标记 |
| CT-08 · P1 | 知识图谱子系统 | 加载 11 板块、41 行业及现有映射。注入悬空边、重复节点、冲突别名和适用模型错误 | 可查询来源、上下游与模型约束。损坏图谱明确失败，映射歧义和模型不适用都有可诊断结果 |
| CT-09 · P1 | 渲染和上传适配器 | 注入浏览器缺失、超时、旧文件、上传失败、返回缺远端 ID、重复重试 | 本地渲染、失败、待上传和远端完成分别可见。只有当前批产物和可核验回执可以进入成功状态 |
| CT-10 · P1 | 四层依赖与入口自检 | 扫描核心、兼容工具、报告、调度的静态及延迟导入。逐一加载正式入口并测试只读路径 | 核心只按允许方向导入，内部用相对导入。逆向依赖、循环和遗漏模块给出具体文件与入口 |
| CT-11 · P1 | Windows 文件提交与备份恢复 | 在隔离目录实测原子替换、文件仍被占用和备份目录重命名 | 成功后可完整重载。环境拒绝访问单独记为环境阻塞，旧版本保持可读，不会把未持久化任务标记完成 |
| CT-12 · P0 | 测试运行隔离 | 运行旧测试和新测试设计中的写入型用例，对比正式账本与代表性产物哈希 | 正式账本和既有档案哈希不变。测试使用本地夹具及临时目录，联网和外部程序调用受到隔离 |

## 四、结合测试 IT

| 编号 | 测试点 | 前置条件与动作 | 预期结果 |
| --- | --- | --- | --- |
| IT-01 · P0 | 授权来源 → 本地归档 → 行情门禁 → 日报 | 用归档的有效行情和一条缺观测时间的行情跑完整链路 | 来源、观测时间、币种、市场和时段在归档、卡片、HTML 和账本间一致。缺观测时间的输入不能用采集时间修补后发布 |
| IT-02 · P0 | 原始财报 → 平账 → 行业映射 → DCF → 档案 | 将同一发行人两种金额单位的项目内底稿分别送入流程，再移除一项关键科目重跑 | 两套单位得到同一可复算结论。缺关键科目时阻断对应计算。净债务、股本、财期和证据 ID 可从档案反查 |
| IT-03 · P0 | 行情门禁 → 期权和风险引擎 → 决策输出 | 用相同标的的有效行情和过期行情分别进入期权估值及配置链路 | 两条估值链复用同一个交易时段判定。过期行情不会生成正式现价、期权信号或配置比例 |
| IT-04 · P0 | 知识图谱 → AI 研判 → 估值状态 → 推荐卡 | 用旧行业别名、错误行业模型和估值区间冲突覆盖三个入口 | 已认可别名能贯通流程。错误模型或评级冲突可定位到输入证据、行业规则和发布判断 |
| IT-05 · P0 | 决策 → 验签 → 文件发布 → 收据 | 分别使用完整与已篡改账本，模拟验签失败前后和文件写入中断 | 只有账本可验、报告内容与记录一致时才发布正式文件。失败时无新增正式预测，收据能解释终止阶段 |
| IT-06 · P0 | 发布后复盘 → 实际行情 → 账本修订 | 登记合法后续行情，验证对账，再注入未来、错误市场、时间戳重复和价格改写 | 复盘只使用允许时点的数据。修订可追溯，预测、对账及复盘可核验，任何异常不会覆盖历史 |
| IT-07 · P1 | 日报即交付 → 公司档案分批流式交付 | 在验收环境让日报先完成，第一批档案可交付，后一批故意失败或延迟 | 日报和首批立即进入交付，不等待后续批次。恢复后只重试需要补交的内容，远端 ID 与产物哈希匹配 |
| IT-08 · P1 | Actions 调度 → 产物归档 → 下一次任务 | 回放两个市场定时事件，强制重跑相同交易日，再执行下一交易日 | 触发和目标市场正确。仅归档本次清单中的产物。新 runner 可接续持久化进度与账本，重跑不会重复发布旧文件 |
| IT-09 · P0 | 资产池 → 逐级覆盖 → 横向拓展 | 构造首期缺一个正式合格标的、首期完成两种情况，再触发 ETF、黄金和成长资产扩展 | 扩展启动受目标版本和正式交付覆盖判定约束。合成、阻断和仅上传未审核档案无法充抵首期完成数 |
