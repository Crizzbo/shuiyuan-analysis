# 水源分析终端交接

## 目标和入口

界面采用浅色、低装饰的工作台样式。主导航保留总览、事件情报、采集中心、计算分析、系统日志和系统设置。原市场和事件视图、个股详情、日志、账本与配置审计继续使用原组件。新能力放在原工作区内。

| 工作区 | 操作 |
| --- | --- |
| 仪表盘总览 | 挂载「任务调度与即时执行中心 (Mission Control)」，支持一键提交 7 类核心后台任务、实时动画运行横幅、分时定时开关与 SQLite 历史流水 |
| 事件情报 | 在事件雷达与官方来源资讯间切换，原雷达的搜索、筛选及详情仍可用 |
| 采集中心 | 查看原采集概览，运行或启停定时任务，查看持久化运行历史和日线归档 |
| 计算分析 | 按代码查询个股，在个股深度研报、自动金融估值走廊和高级自定义测算间切换 |
| 自动金融估值走廊 | 彻底告别人工手动填表。系统从 SEC 10-K 原档、实时基准行情与 FRED 美债收益率中全自动提取已平账企业自由现金流 (FCF)、稀释股数、净现金结构与 WACC 折现率，自动代入多阶段 DCF 估值模型，生成悲观底线、中性公允与乐观靶心三态估值走廊及通俗商业直觉结论，支持敏感性微调 |
| 高级自定义测算 | 保留作为辅助工具，支持自定义假设下的净现值 NPV、内部收益率 IRR 及单一财务比率计算 |

### 六大任务执行能力覆盖 (Mission Control Task Capabilities)

1. **跑任务 (Task Execution)**：总览控制台与采集中心支持即时运行任务、活跃运行中任务横幅 (`active_runs`) 与 SSE 实时状态流同步。
2. **金融计算 (Financial Calculations, `FINANCE_CALC`)**：全自动批量遍历核心资产池（NVDA, AAPL, MSFT, AMD, GOOGL, META, TSM, 8035 等），自动带入官方财报三表原档、现价与 FRED 宏观美债无风险利率，调用底层纯净金融计算引擎执行多阶段 DCF 估值走廊、WACC 资本成本与杜邦盈利分析，生成全息对账结果并持久化到 `.cache/terminal/finance_calc_latest.json`，杜绝机械打分与手工填表。
3. **股票收集与形态初筛 (Stock Screening, `STOCK_SCREENING`)**：全市场标的收集，0-Token 纯本地 50/150/200日均线、52周高低点及 VCP 波动收缩第二阶段形态初筛。
4. **信息分时间采集 (Time-Phased Ingestion, `OFFICIAL_NEWS`)**：每小时脉冲巡检 SEC、东证等官方财经信源，自动过滤去噪与隔离传闻。
5. **指标更新与宏观测算 (Indicator Calculations, `INDICATOR_UPDATE`)**：每小时自动计算 10年期美债收益率 (DGS10)、联邦基金利率 (EFFR)、VIX 波动率、USD/JPY 汇率与 50日/200日均线上方股票市场宽度占比。
6. **数据拉取任务 (Data Fetching Jobs, `US_DAILY` / `JP_DAILY`)**：分别于东京时间 07:00（美股收盘）与 16:00（日股收盘）分时抓取日线 OHLCV 与 FRED 宏观时序，写入内容寻址归档并经由 SHA-256 验签。
7. **本地数据与账本核验 (`LOCAL_AUDIT`)**：资产负债表平账断言与 PredictionLedger SHA-256 密码学时间链条验签。

在项目根目录执行以下命令，浏览器打开 `http://127.0.0.1:8765`。

```powershell
python scripts/build_web.py
python scripts/serve_watersource_terminal.py
```

加 `--manual-only` 可进行本地验收并手动提交任务。定时调度由 Python 服务进程执行，关闭浏览器后仍可继续。关闭服务或电脑会停止调度。当前未注册系统开机服务。

## 实现位置

- [前端工作区与计算入口](../web/src/App.tsx) 负责导航、金融计算表单和任务交互。原工作区组件位于 `web/src/components/` 目录。
- [HTTP 服务](../scripts/serve_watersource_terminal.py) 托管构建后的前端，并连接任务队列。POST 使用同源检查。计算经由 [终端聚合层](../financial_reporting/watersource_terminal_service.py) 调用 [登记的金融计算服务](../finance_tools/governance_and_pipeline/service.py)。
- [后台队列](../scripts/terminal_scheduler.py) 在 `.cache/terminal/` 保存任务、开关和来源级检查点，最多三个工作线程。同名任务不会同时执行，同一任务和定时时隙只入队一次。重启后重新领取未完成的运行，校验已归档的检查点后继续。
- [采集入口](../scripts/ingest_data.py) 复用 [允许来源配置](../data/ingestion-sources.json) 和原有内容寻址归档。当前覆盖核心美股与日股日线、FRED 宏观序列、配置中的官方及发行人 RSS。归档成功只表示取得了来源响应，交易日期和发布时点另行展示。
- [样本排除清单](../config/terminal-evidence-exclusions.json) 隔离此前写入的 24 份报价样本和已识别的雷达样本。终端读路径过滤样本，报价按市场时间重验，已有业务档案保留供追溯。历史模拟初筛在终端中标为待核验，不能产生正式候选。

## 运行和验收

- 东京时间周二至周六 07:00 触发美股，周一至周五 16:00 触发日股。资讯每小时触发。当前按工作日窗口排队，尚未接入交易所节假日日历。同一市场在休市日可能取得历史日线。
- 前端构建通过。终端 API、计算器、行情归档追踪和队列测试共 15 项通过，覆盖两个任务并行、定时去重、重启恢复、断点摘要校验及无效 DCF 参数拦截。另以已知结果校对了 WACC、NPV、IRR 和毛利率。
- 架构巡检、数据治理、知识结构、六步研究契约、行业映射和预测账本验签已通过。最近一次完整的仓库回归执行了 909 项，出现 4 个断言失败及 26 个错误。已核实的问题包括缺少公司代表样本档案、已核验批次索引为空，以及风险模型原因码与断言不一致。加入来源级检查点后，定向回归通过，全量重跑长时间没有继续输出，已中断。最近一次重跑的部分日志在 `.cache/terminal-unittest.log`。
- 当前会话的 Windows 沙箱阻止回环 HTTP 客户端连接。接口验证使用内存分派。真实浏览器操作、联网来源响应和长期守护进程尚未验收。

## 后续接入

1. 逐市场验收真实联网归档，补入交易所节假日日历。以归档里的最新交易日判定当日覆盖，单独区分行情快照、日线、成交量和财报三表。
2. 把可追溯的日线接入 SEPA 输入适配和全资产池分块。当前 `scripts/run_screening_universe_batch.py` 仍有基于股票代码哈希的模拟输入，正式任务必须使用真实 OHLCV；只有第二阶段和形态收敛条件全部通过才进入深度分析。
3. 对接官方三表、日股披露、雷达证据核验、研报与档案生产。用已授权宿主接入 Google Sheets，浏览器补数走官方原文和归档流程，保持最新证据可追溯。上传管线应以研报或档案批次就绪为触发条件，并用实际 Drive 回执更新完成状态。
4. 补齐全量测试依赖的项目内证据及基线契约，在全量门禁通过后再部署长期运行。
