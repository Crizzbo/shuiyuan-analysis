## 一、 功能背景与业务用途

### 1. 业务背景
面对美股与日股数千家上市公司的全息投研需求，传统串行离线批处理存在两大痛点：一是全量生成耗时过长，无法在早 07:00（美股收盘）与 16:00（日股收盘）窗口期内准时交付；二是当发生进程异常中断时，缺乏可靠的断点恢复机制，导致重复耗费 I/O 资源。本功能构建分批切片（Batch Chunking）、内存 $O(1)$ 寻址、三表刚性平账自检及边渲染边流式落盘的工业级批量数据交付流水线。

### 2. 核心用途
本功能解决三大管道工程问题：
1. **千家标的高吞吐流式调度 (Chunk-and-Stream)**：按 50 家标的为一个切片批次，每就绪一批即刻触发多模态文件落盘与云端同步，实现高吞吐持续交付；
2. **原子化断点续跑状态机**：通过操作系统级 `.tmp` 原子替换机制保证执行进度持久化防损坏，支持异常中断后秒级增量恢复；
3. **资产负债刚性平账自检 ($Assets = Liabilities + Equity$)**：在装配档案前执行严格会计配平自检，自动拦截平账残差 $> 0.1\%$ 的异常数据，杜绝虚假财报进入买方决策层。

### 2. 数学公式定义与推导

1. **资产负债表刚性配平检验公式**：
   $$\text{Balance Discrepancy} = \frac{|\text{Total Assets} - (\text{Total Liabilities} + \text{Total Equity})|}{\max(|\text{Total Assets}|, 1.0)}$$
   - 检验判定：当 $\text{Balance Discrepancy} \le 0.1\%$ 时判定合规；若大于 $0.1\%$ 则触发熔断拦截。
2. **存货周转天数 (DIO) 供应链风险测算**：
   $$DIO = \frac{\text{Average Inventory}}{\text{Cost of Goods Sold (COGS)}} \times 365$$
3. **安全边际率 (Margin of Safety)**：
   $$\text{Margin of Safety} = \frac{\text{Fair Value Per Share} - P_{\text{current}}}{P_{\text{current}}} \times 100\%$$

## 五、 状态机与标的执行生命周期 (State Registry)

### 1. 批量调度状态空间映射表

| 状态代号 | 英文枚举标识 | 中文状态名称 | 触发条件 | 下一步调度动作 |
| :--- | :--- | :--- | :--- | :--- |
| `ST_01` | `PENDING` | 待调度排队 | 标的已索引，等待批次分配。 | 进入批次内存加载。 |
| `ST_02` | `PROCESSING` | 正在渲染装配 | 正在执行三表平账与 Excel 建造。 | 写入 `.tmp` 临时文件。 |
| `ST_03` | `COMPLETED` | 成功落盘交付 | 多模态文件原子替换成功。 | 标记完成，支持断点跳过。 |
| `ST_04` | `DEFICIENT_BLOCKED`| 平账失败拦截 | 资产不平衡度 $> 0.1\%$ 或三表缺失。 | 阻断落盘，转入补数清单。 |
| `ST_05` | `STALE_REJECTED` | 时效超期拒收 | 行情时间戳早于前一交易日收盘。 | 告警拦截，等待行情刷新。 |

## 附录：工程实现与边界自查清单 (Engineering Defense Checklist)

- [ ] **物理临时文件防污染**：任何文件写入必须先输出至 `.tmp` 临时扩展名文件，经校验无误后方可执行 `os.replace` 原子替换，严禁留下半截残损文件。
- [ ] **内存寻址时间复杂度**：全局底账加载必须保持在 $O(1)$ 哈希寻址，严禁在遍历标的时对磁盘进行重复递归扫描。
- [ ] **平账绝对阈值拦截**：平账容差不得超过 $0.1\%$，任何未平账或伪造数据严禁通过参数绕过自检。
- [ ] **路径跨平台兼容性**：所有输出目录与文件解析必须使用 `pathlib.Path`，严禁死代码硬编码 Windows 反斜杠绝对路径。
