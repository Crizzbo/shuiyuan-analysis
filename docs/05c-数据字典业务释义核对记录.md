# 数据字典业务释义核对记录

文档版本：1.3.0；契约版本：1.0.0；日期：2026-10-11。

## 1. 核对范围与依据

核对 30 份单表的 247 处字段定义；依据为项目内正式 Schema、研究校验器、资料目录实现、六步流程和周期框架。没有访问外部资料。本次只修正文档、释义维护方式及文档检查，不修改金融方法或现有数据契约。

根因是原生成器主要按属性短名称套用解释，容易把不同对象的 `version`、`status`、`claim_refs`、期间等字段混为一谈；另有部分填写建议被描述成已经自动实施的规则。现在每个完整字段标识均有独立释义源，新增字段没有释义时不得生成。

## 2. 主要修正

| 字段／范围 | 原说明问题 | 修正后的业务含义及限制 |
|---|---|---|
| observation.value | “数值或数量对象”容易让人直接填数字 | 有值必须为 quantity 对象，缺失才为 null |
| scenario.probability | 声称默认 null | 没有默认值；必须显式填值或 null，完成 S4 时核对三情景完整性 |
| segment.weight_evidence_refs | 禁止与分类证据使用同一资料 | 同一资料可以同时支持权重和分类，应核对内容是否确实支持 |
| segment.weight | 未解释利润占比的结构限制 | 占比限定 0—1，遇负利润或大于 1 的真实占比，本版无法直接表达，应登记缺失并解释 |
| subject.is_adr | 暗示每个证券都有独立标记 | 当前只有 subject 层概括标记，多证券差异需说明 |
| available_at | 一概描述为首次公开可得 | 区分资料版本及观测口径的可得时点，不沿用旧版时间 |
| period.start／end | 将历史截止日与顺序要求泛化到所有窗口 | 历史观测、权重期间和未来预测窗口分别解释；并非全部窗口都有相同自动检查 |
| snapshot.version | 与前序依赖版本混用 | 记录失效前的基线旧版本；dependency.version 才是当前输入采用的前序版本 |
| gate.result／reason | 易与步骤状态或业务判断混淆 | 验收结果为 pass／fail／not_applicable；文字理由是否充分需人工复核 |
| crosscheck_calculation_refs | 将列表比较写成集合独立性验证 | 当前程序比较列表是否完全相同，方法独立性及排序规避须人工复核 |
| permanent_loss_risks | 易误填风险字符串清单 | 每项为 assessment 对象，包含结论、判断引用及局限 |
| position_fraction | 未说明比例的目标及分母局限 | 是研究提出的仓位占比，非成交记录；组合分母口径尚未结构化 |
| validated_rule_refs | 把字段存在与统计验证混为一谈 | 现使用 industry_id 作为键；只在行动条件满足时强制检查验证状态 |
| last_observation_ref | 暗示引用一定是最新且有效观测 | 当前只检查引用存在，未检查与计划指标一致、最新或非缺失 |
| new_evidence_refs | 易被理解为新发布资料 | 指本次复盘新纳入考虑的资料，可早已发布或登记 |
| changed_claim_refs | 暗示保存旧判断和差异 | 仅引用当前判断 ID；旧内容需结合历史修订查询 |
| trigger 条件与 target_steps | 易被理解为自动执行机制 | 是计划与文字条件；不会自动取数、判断或创建实际失效事件 |
| 生命周期维度 | 易混同产品发展阶段与所有周期 | 长期发展、供需、盈利、融资、情绪、定价分别评估，依据项目周期框架 |

## 3. 当前实现边界

业务上应检查、但当前未完整自动实施的事项已在对应字段说明中标明，包括证券属性逐项映射、交易日历、分部占比合计及口径一致性、触发器 ID 唯一性、窗口顺序与期限一致性、监测观测与指标匹配、计算独立性以及文字解释充分性。列出这些差距不等于功能已实现。

字段、引用和结构一致性检查是工程验证，不证明经济判断或估值正确。后续变更业务规则时，应同时核对释义源、Schema、实现和适用示例，而非仅靠字段覆盖数判断质量。
