# 免费数据接入管道与浏览器补数操作技术设计规格书 (Free Data Ingestion & Browser Replenishment SOP)

> **功能标识**：`FREE_DATA_INGESTION_SOP_SPEC`  
> **所属业务分类**：类别 E：底层数据工程层面（8 类免配置公共数据采集、6 类商业接口硬拦截、只读归档哈希固化与 AI 浏览器补数流程）  
> **技术成熟度**：生产基准 (Production)  
> **单一事实来源**：  
> - 采集调度主脚本：`scripts/ingest_data.py`  
> - 浏览器导入适配器：`scripts/import_browser_source.py`  
> - 采集核心引擎：`financial_reporting/data_collection_gateway.py`  
> - 数据计划契约：`examples/free-data-*.json`  
> - 自动化测试套件：`scripts/test_data_ingestion.py`  

---

## 一、 功能背景与业务用途

### 1. 业务背景
在买方证券投研系统的日常运作中，外部市场行情、宏观经济序列及上市公司官方财报的获取面临两大挑战：一是商业数据接口通常要求收费 Key 或个人身份凭据，若在代码中索取或硬编码凭据，极易造成生产事故与账户越权风险；二是若缺乏统一的免配置采集规范，上层分析模块可能直接发起高频无序网络请求，引发目标官方网站的封禁或引入未经核实的脏数据。依据本项目 2026-10-11 最新免配置数据来源策略，本规范确立 8 类公开免配置来源白名单、6 类商业认证接口物理硬拦截、零付费依赖及 AI 浏览器官方原版补数的标准作业程序。

### 2. 核心用途
本功能解决全系统三大数据采集与补数运维问题：
1. **标准化命令行数据接入 (Ingest CLI)**：通过 `scripts/ingest_data.py` 调度批处理计划（行情计划、公开宏观计划、发行人财报计划），实现断点续采与离线回放；
2. **商业凭据物理硬拦截与降级补数**：对需要 API Key 的接口物理置为 `enabled=false`，自动将缺失数据降级为标准化浏览器补数任务清单；
3. **不可变对象库固化与哈希验签**：所有抓取或导入的文件，先在本地生成 SHA-256 签名并落盘为 `.blob` 不可变对象，再提供给下游模型使用。

## 二、 系统架构上下文与依赖关系

### 1. 前置依赖 (Inputs From Upstream)
- `examples/free-data-*.json`：提供采集任务执行计划。
- 公开免配置端点（FRED CSV、BLS 公开序列、日本央行 BOJ、TDnet、GDELT、yfinance）。
- AI 浏览器：提供官方 SEC/EDINET 经核验的原文下载路径。

### 2. 后置消费 (Outputs To Downstream)
- `data/catalog/`：存储不可变对象与元数据。
- `data/browser-search/replenishment_tasks.json`：接收拦截后的待补数清单。
- `financial_core/`：消费经来源凭据审计的高置信度事实。

### 3. 数据流转时序图
```
┌──────────────────────────────────────┐
│  采集任务计划 (free-data-plan.json)  │
└──────────────────┬───────────────────┘
                   │ (解析命令行参数并调度)
                   ▼
┌──────────────────────────────────────┐
│  数据接入中枢 (ingest_data.py)       │
│  ├── 检查来源白名单 (8 类免配置)     │
│  ├── 拦截 6 类 Key 接口 ──► 生成补数清单

```

## 三、 输入参数契约说明 (Input Contracts)

CLI 命令行调度参数与采集计划核心字段规范如下表：

### 1. CLI 命令行参数规范
| 命令行选项 | 参数类型 | 默认值 | 约束条件 | 业务功能说明 |
| :--- | :---: | :---: | :---: | :--- |
| `command` | `str` | 必填位置参数 | `status/run/audit` | 调度指令（检查状态、执行计划、审计结果）。 |

| `--refresh` | `flag` | `False` | 布尔值 | 强制跳过本地有效缓存，重新发起网络请求。 |
| `--offline` | `flag` | `False` | 布尔值 | 纯离线模式，仅读取本地已有成功记录，严禁联网。 |

### 2. 采集计划 JSON 字段契约
| 顶级字段标识 | 数据类型 | 必填性 | 取值范围 | 业务释义 |
| :--- | :---: | :---: | :---: | :--- |
| `plan_id` | `str` | 必填 | 唯一字符串 | 采集批次全局业务标识符。 |
| `tasks` | `list` | 必填 | 任务对象列表 | 包含的具体采集工位列表。 |
| `task.provider` | `str` | 必填 | 见来源白名单 | 数据提供商代号（如 `yfinance`, `fred_csv`, `boj`）。 |
| `task.dataset` | `str` | 必填 | 字符串 | 目标数据集名称（如 `daily`, `series`, `document`）。 |

### 2. 核心数学模型推导

1. **漏桶算法平滑限流模型 (Leaky Bucket)**：
   $$\Delta t_{\text{sleep}} = \max\left(0.0, \; \frac{1.0}{r_{\text{max}}} - (t_{\text{current}} - t_{\text{last\_request}})\right)$$
   对所有免配置端点施加 $\Delta t \ge 0.5\text{s} \sim 1.0\text{s}$ 的强制保护，杜绝突发突发轰炸导致 IP 被封。
2. **文件完整性与密码学摘要验证**：
   $$\text{Digest} = \text{SHA-256}(\text{FileBytes})$$
   断言导入的原文文件指纹与收据中登记的指纹严格一致，防止磁盘损坏或篡改。

## 五、 状态机与任务状态空间 (Task Lifecycle Registry)

### 1. 采集任务执行状态空间映射表

| 状态代号 | 英文枚举标识 | 中文状态名称 | 判定特征 | 系统后续动作 |
| :--- | :--- | :--- | :--- | :--- |
| `TSK_01` | `collected` | 采集成功态 | 接口返回有效数据，哈希落盘成功。 | 标记成功，数据存入不可变库。 |
| `TSK_02` | `no_data` | 有效无记录态 | 参数合规但上游无匹配数据（如非交易日）。| 记录为正常空值，不发起重试。 |
| `TSK_03` | `needs_config`| 需凭据拦截态 | 请求属于已停用的 6 类商业 Key 接口。 | 阻断执行，生成浏览器补数清单。 |
| `TSK_04` | `rate_limited` | 触发限流态 | 上游返回 HTTP 429 或连接被重置。 | 自动指数退避重试，记录告警。 |
| `TSK_05` | `offline_miss` | 离线未命中态 | 开启 `--offline` 但本地无有效缓存。 | 明确抛出缺失，严禁伪造虚假数据。|

```json

  "executed_at": "2026-11-03T16:00:00Z",
  "total_tasks": 3,

    {
```

### 输出字段逐项业务释义
| 输出字段名称 | 字段标识 | 数据类型 | 计量单位 | 业务释义 |
| :--- | :--- | :---: | :---: | :--- |

## 附录：工程实现与边界自查清单 (Engineering Defense Checklist)

- [ ] **严禁读取或索取 6 类商业 API Key**：系统在任何情况下均不得索取 `SEC_USER_AGENT`、`EDINET_API_KEY`、`JQUANTS_API_KEY` 等认证凭据。
- [ ] **严格遵守漏桶限流时间间隔**：所有网络抓取请求之间必须执行安全延迟休眠，严禁并发循环轰炸公共免费服务器。
- [ ] **部分成功严禁谎报全量成功**：若计划中存在任意一个失败或被拦截任务，CLI 必须以非零状态退出，严禁掩盖错误。
- [ ] **禁止将中间临时值当作官方事实**：通过 yfinance 等公开接口抓取的清洗价格，仅能作为二级行情观察，严禁标为经审计的原始财报事实。
- [ ] **浏览器补数导入路径防越界**：调用 `import_browser_source.py` 时传入的文件路径必须经过规范化与项目根目录边界检验，严禁路径遍历。
