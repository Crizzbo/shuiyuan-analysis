## 一、 功能背景与业务用途

### 1. 业务背景
在买方机构自动化投研系统的构建过程中，随着代码量与模型复杂度的指数级增长，系统极易在缺乏严格架构审计的情况下出现“架构劣变与虚假繁荣”。2026-10-14 开展的系统全景工程审计，对项目内本地代码、契约定义、文档规范及离线测试进行了穷尽式法证排查，定位出影响系统生产可用性的十大核心技术缺陷（R01~R10），涵盖四大系统性风险：
1. **假数据生成与穿透污染 (R01, R03)**：部分批量生成器通过代码哈希取模生成虚假财务科目，甚至自动载入硬编码未核验样本，绕过底层证据治理直接产出虚假买入评级；
2. **时效与财务刚性门禁形同虚设 (R02, R06)**：行情新鲜度缺乏时钟日历校验导致历史或异常日期冒充盘中实时；资产负债表平账检验仅赋值布尔变量却未执行执行阻断；
3. **金融数学推导断裂与标签伪造 (R04, R05, R07, R08)**：宏观折价参数错接导致压力测试归零；固定倍率区间冒充差异化多情景 DCF；固定演示比例冒充半凯利最优仓位；现金消耗模型错误导致正现金流企业产生有限跑道警报；
4. **流式并发事务与模块导入破损 (R09, R10)**：流式批处理将上传失败误标为完成且无锁并发竞争导致账本覆盖；对外模块命名不一致引发运行时导入异常。

本规格书确立四大层级严格物理隔离、R01~R10 缺陷的根治性整改标准与不可逾越的买方工程安全网。

### 2. 核心用途
本功能解决全系统三大工程治理与架构防劣变基石问题：
1. **四层单向物理隔离与零逆向依赖 (Four-Tier Decoupling)**：确立 `financial_core/`（纯净金融核心）➔ `finance_tools/`（中继工具）➔ `financial_reporting/`（报告呈现）➔ `scripts/`（调度器）的单向拓扑，严禁逆向污染；
2. **R01~R10 十大核心缺陷根治性清零与断言锁死**：将所有审计缺陷转化为不可逆的自动化单元与集成测试用例，确保修改前后具备可审计、防伪断言与物理拦截能力；
3. **去工程符号化与买方合规门禁闭环**：杜绝向用户暴露工程变量或代码代号，全面转为商业业务语义；在证据不足或平账失败时刚性中断后续估值与发布管线。

### 2. 核心数学模型推导

1. **架构依赖单向性纯度方程**：
   $$\text{ReverseDependencyRatio} = \frac{\sum_{m \in \text{financial\_core}} \mathbb{I}(\text{Imports}(m) \cap \{\text{finance\_tools}, \text{scripts}, \text{reporting}\} \neq \emptyset)}{|\text{financial\_core}|} \equiv 0.0$$
   底层金融核心层逆向依赖率必须恒等于零，任何逆向引用一票否决。
2. **净现金消耗率 (Net Cash Burn Rate) 正确推导方程**：
   $$\text{NetBurn} = \max(0.0, \text{CapEx} - \text{CFO})$$
   当 $CFO \ge \text{CapEx}$ 时，$\text{NetBurn} \equiv 0.0$，标的处于正向造血盈利状态，严禁报告有限现金跑道风险。
3. **真实所有者自由现金流方程**：
   $$FCF_{\text{owner}} = CFO - \text{CapEx} - SBC$$
   严禁将股份支付薪酬（SBC）视作非现金加回项而不作股东权益稀释扣减。

## 附录：工程实现与边界自查清单 (Engineering Defense Checklist)

- [ ] **严禁破坏四层单向物理隔离**：`financial_core/` 必须保持纯净独立，严禁导入 `finance_tools`、`scripts` 或任何外层模块。
- [ ] **严禁使用模板或随机数伪造财务**：所有进入主管道的企业财务数据必须来自于官方原件与不可变封套，严禁哈希取模生成假数据。
- [ ] **资产负债表平账千分之一刚性熔断**：平账不通过必须直接抛出异常中断执行，严禁仅记录布尔状态而放行下游估值。
- [ ] **行情新鲜度必须具备物理时钟与日历核验**：旧数据必须明确标注为前收盘基准，严禁仅凭静态字符串赋予实时行情徽标。
- [ ] **全量回归测试零失败交付底线**：任何代码提交前必须执行 449 项全量测试矩阵，确保测试用例数量只增不减且 100% 全部 PASS。
