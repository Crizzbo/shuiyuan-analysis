> **功能标识**：`BATCH_PIPELINE_OPERATIONAL_SOP_SPEC`  
> **所属业务分类**：类别 E：底层数据工程与批处理调度层面（全量资产池流式建档、三表平账刚性门禁、原子断点持久化与故障自愈）  
> **技术成熟度**：生产基准 (Production)

## 一、 功能背景与业务用途

### 1. 业务背景
在买方机构面向美股（10,000+ 上市主体）与日股（4,400+ 上市主体）全量资产池建立全息投研档案时，长时间批量批处理面临三大系统性工程风险：一是由于进程异常终止、网络抖动或操作系统重启导致的大规模重复计算，浪费算力且无法保证历史幂等性；二是由于缺少前置三表配平自检，导致残缺或未经审计的虚假财务数据流入下游报告，引发严重的投研误导；三是并发写入时容易损坏本地单文件状态数据库，引发状态不一致。本规范确立标准化命令行调度矩阵、原子 `.tmp` 状态持久化、刚性平账自检拦截及秒级断点续跑机制。

### 2. 核心用途
本功能解决全系统三大批量生产与运维调度问题：
1. **千家标的自动化批量建档**：通过 `--expand-reconciled` 将全量标的切分为标准批次（Batch Chunking），边清洗边装配 5-Sheet Excel 与 JSON 深度档案；
2. **三表配平刚性前置拦截**：严格断言 $|Total Assets - (Total Liabilities + Total Equity)| \le 0.1\%$，对不平账标的刚性拦截并自动登记至待补数清单；
3. **断点无损秒级自愈 (Atomic Resume)**：依托操作系统底层原子替换机制（Atomic File Replace），实现中断后秒级跳过已完成项，实现零重复计算。

## 三、 输入参数契约说明 (Input Contracts)

批量流水线命令行核心参数定义如下表：

| 命令行参数 | 参数类型 | 默认值 | 取值范围 | 业务功能说明 |
| :--- | :---: | :---: | :---: | :--- |
| `--batch` | 整数 | `None` | 正整数 | 仅执行指定的单一批次（如 `--batch 1`）。 |
| `--batch-range` | 字符串 | `None` | `START-END` | 执行连续批次区间（如 `--batch-range 1-10`）。 |
| `--expand-reconciled`| 标志位 | `False` | 布尔值 | 启用增量切片扩展，合并 333 家平账标的跨越千家规模。 |
| `--resume` | 标志位 | `True` | 布尔值 | 启用断点续跑，自动跳过已完成项。 |
| `--limit` | 整数 | `None` | 正整数 | 限制本次运行最大完成标的数（用于冒烟验证）。 |
| `--delay` | 浮点数 | `0.05` | $\ge 0.0$ | 单标的处理后的防锁休眠间隔（秒）。 |

### 2. 核心数学模型推导

1. **资产负债表刚性配平自检方程**：
   $$\text{Discrepancy} = \frac{|\text{Total Assets} - (\text{Total Liabilities} + \text{Total Equity})|}{\max(|\text{Total Assets}|, 1.0)}$$
   判定门限：$\text{Discrepancy} \le 0.001$（$0.1\%$ 容差）。
2. **批处理进度百分比方程**：
   $$\text{ProgressPct} = \frac{|\text{CompletedSet}|}{|\text{TargetUniverse}|} \times 100\%$$
3. **断点持久化原子写入操作序列**：
   $$\text{WriteTemp}(\text{state}, \text{path.tmp}) \xrightarrow{\text{fsync()}} \text{AtomicReplace}(\text{path.tmp}, \text{path.json})$$

## 五、 状态机与生命周期 (State Registry)

### 1. 批量流水线单标的执行状态空间

| 状态代号 | 英文枚举标识 | 中文状态名称 | 判定特征 | 系统动作 |
| :--- | :--- | :--- | :--- | :--- |
| `PST_01` | `COMPLETED` | 成功建档态 | 三表平衡，指标计算完成，报告生成落盘。 | 记录进度，后续批次自动跳过。 |
| `PST_02` | `SKIPPED` | 断点跳过态 | 状态机已存在完成记录且开启 `--resume`。 | 零运算跳过，直接推进至下一标的。|
| `PST_03` | `DEFICIENT_PENDING`| 拦截待补数态| 三表底账缺失或配平误差 $> 0.1\%$。 | 阻断建档，自动登记至补数清单。 |
| `PST_04` | `RUNTIME_ERROR` | 执行异常态 | 运算发生非预期未捕获异常。 | 记录错误日志，保存上下文现场。 |

## 附录：工程实现与边界自查清单 (Engineering Defense Checklist)

- [ ] **状态机写入必须采用原子替换**：状态机保存必须先写入 `.tmp` 临时文件，通过 `os.replace()` 原子替换目标文件，严禁直接原地覆盖写入。
- [ ] **严禁跳过资产负债平衡自检**：所有录入流水线的财报数据必须满足配平容差 $\le 0.1\%$，平账失败必须拦截，严禁代码自动强平虚假数字。
- [ ] **断点续跑必须保持幂等性**：在开启 `--resume` 状态下，针对已完成标的必须做到零额外开销跳过，保证多次调度产物完全一致。
- [ ] **缺失标的刚性写入补数清单**：被拦截的标的必须即时登记入 `replenishment_tasks.json`，严禁静默丢弃或报错终止整批运行。
- [ ] **单标的防锁延迟保护**：批量运行中每完成一个标的必须执行 `--delay` 冷却，防止突发连续磁盘 I/O 导致文件锁死。
