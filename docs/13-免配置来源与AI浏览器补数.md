# 免配置公开来源与 AI 浏览器官方补数技术设计规格书 (Zero-Config Sources & AI Browser Replenishment Spec)

> **功能标识**：`ZERO_CONFIG_SOURCES_AND_BROWSER_REPLENISHMENT_SPEC`  
> **所属业务分类**：类别 E：底层数据工程层面（零配置公开来源白名单、认证接口硬阻断、AI 浏览器官方监管直达、只读原版下载与证据哈希闭环）  
> **技术成熟度**：生产基准 (Production)  
> **单一事实来源**：  
> - 补数任务主清单：`data/browser-search/replenishment_tasks.json`  
> - 官方原件导入器：`scripts/import_browser_source.py`  
> - 证据目录与持久化：`scripts/data_catalog.py` 与 `scripts/data_store.py`  
> - 自动化测试集：`scripts/test_data_store.py`

## 一、 功能背景与业务用途

### 1. 业务背景
在买方机构研究与量化底账治理中，传统外部商业数据接入普遍面临“API 依赖陷阱”与“账户隐私泄露”两大风险。常见工程缺陷包括：一是强依赖商业付费 API Key、邮箱账户或未经验证的第三方爬虫插件，一旦鉴权失效或限流即导致整盘流水线瘫痪；二是在缺乏官方底稿时，部分自动化流程倾向于调用未经审计的大语言模型生成“幻觉财务数字”或拿不具备法律效力的二次二手聚合页数据冒充审计底稿；三是私自扫描用户本地个人下载目录，引发数据越权与隐私合规风险。依据本项目 2026-10-11 最新数据策略，系统全面确立“零配置公开来源优先、认证接口全面硬拦截、缺失数据由 AI 浏览器定向检索官方原版、只读导入并锁定 SHA-256 哈希”的数据治理准则。

### 2. 核心用途
本功能解决全系统三大数据获取与治理问题：
1. **八大免配置公开来源白名单管理**：严格运行 FRED CSV、BLS V1、BOJ、GDELT、RSS、TDnet 公开浏览、yfinance 与发行人官方 IR 八类公开免配置通道；
2. **六大需配置适配器物理硬拦截**：对需要 API Key 或账号认证的旧接口（SEC 身份接口、EDINET、J-Quants、Alpha Vantage、FRED Key、e-Stat）执行 HTTP 与任务层双重物理拦截 (`enabled=false`)；
3. **AI 浏览器定向补数标准作业程序 (SOP)**：当检测到官方三表缺失时，自动生成包含 SEC EDGAR / TDnet 直达链接的标准化待补数任务清单，通过 AI 浏览器下载官方 PDF/XBRL 原版，并由 `import_browser_source.py` 执行只读单向导入与密码学固化。

## 二、 系统架构上下文与依赖关系

### 1. 前置依赖 (Inputs From Upstream)
- `scripts/run_567_universe_batch_pipeline.py`：在执行平账前置门禁时探测缺失底账标的。
- 官方监管系统（SEC EDGAR 浏览页、东证 TDnet、BOJ、FRED）：提供公开无需鉴权的官方网页。

### 2. 后置消费 (Outputs To Downstream)
- `data/catalog/objects/{hash}.blob`：落盘只读不可变原始财报与宏观底稿。
- `data_sources/official_filings/`：提供经 $A = L + E$ 平账自检通过的标准财务底账。
- `scripts/data_store.py`：消费来源登记凭证更新全局数据底账。

### 2. 核心数学模型推导

1. **原始文件密码学指纹生成方程**：
   $$\text{Digest} = \text{SHA-256}(\text{FileBytes}) = \sum_{b \in \text{Bytes}} \text{Chamber}(b)$$
   生成 64 位不可逆十六进制摘要，作为 `data/catalog/objects/` 下的唯一寻址文件名。
2. **三表底账刚性平账自检容差不等式**：
   $$\text{Discrepancy} = \frac{|\text{Total Assets} - (\text{Total Liabilities} + \text{Total Equity})|}{\max(|\text{Total Assets}|, 1.0)} \le 0.001$$
   超出 $0.1\%$ 容差直接拒绝入库，判定为非标准或残缺原件。
3. **存货周转天数 (DIO) 营运效率计算**：
   $$DIO = \frac{\text{Average Inventory}}{\text{COGS}} \times 365$$

## 五、 状态机与来源治理空间 (State Registry)

### 1. 数据来源治理生命周期状态空间

| 状态代号 | 英文枚举标识 | 中文状态名称 | 判定特征 | 系统处理动作 |
| :--- | :--- | :--- | :--- | :--- |
| `SRC_01` | `ZERO_CONFIG_PASS`| 免配置合规态 | 属于八大白名单公开来源，零鉴权运行。 | 放行采集与离线归档。 |

## 附录：工程实现与边界自查清单 (Engineering Defense Checklist)

- [ ] **严禁向用户索取商业 API Key**：系统严禁向用户索取任何商业数据接口密钥或账号密码，杜绝付费 API 依赖。
- [ ] **严禁扫描用户个人下载目录**：导入程序仅允许只读接收确切传递的文件绝对/相对路径，严禁遍历或扫描操作系统的 Downloads 目录。
- [ ] **严禁 AI 模型幻觉填充财务数字**：三表底稿必须直接来自官方监管披露原件，严禁大语言模型生成伪造数据替代真实事实。
- [ ] **官方检索链接白名单限制**：生成的定向补数检索链接仅限于 SEC EDGAR、东证 TDnet 及金融厅 EDINET 官方域名。
- [ ] **只追加不可变存储断言**：导入的 `.blob` 物理文件严禁执行物理覆盖或删除，必须严格保持追加写入。
