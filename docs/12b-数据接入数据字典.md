# 数据接入数据字典与中间暂存层实体契约技术设计规格书 (Data Ingestion Dictionary & Staging Entity Schema Spec)

> **功能标识**：`DATA_INGESTION_STAGING_DICTIONARY_SPEC`  
> **所属业务分类**：类别 E：底层数据工程层面（Staging 数据暂存层、来源配置元数据、采集任务生命周期、不可变对象归档与浏览器回执对齐）  
> **技术成熟度**：生产基准 (Production)

## 一、 功能背景与业务用途

### 1. 业务背景
在买方证券投研系统的外部数据获取中，原始网页、API 报文或下载的财报 PDF 属于未受信任、未经清洗的外部暂存数据（Staging Layer）。若直接将这些多源异构、结构不一的原始片段写入核心正式研究知识库，极易引发字段污染、口径错乱和历史证据不可追溯。本规范确立统一的五大实体数据契约模型（`Source` ➔ `Job` ➔ `Artifact` ➔ `Result` ➔ `BrowserReceipt`），规范中间暂存层的所有表结构、状态空间与哈希校验标准，构建从外部网络到内部正式事实的防污染隔离带。

### 2. 核心用途
本功能解决全系统三大数据接入治理与实体定界问题：
1. **五大暂存实体全息解耦 (5-Entity Staging Architecture)**：清晰界定“数据源配置 (Source)”、“采集工位作业 (Job)”、“不可变原始资料归档 (Artifact)”、“规范化产出 (Result)”与“浏览器人工核验回执 (BrowserReceipt)”的数据字典与约束规则；
2. **供应商原字段物理隔离原则**：保持各外部提供商（yfinance, SEC, FRED, TDnet）的原始字段名与层级不变，严禁在接入暂存层伪造统一财务字段定义；
3. **不可变对象指纹锁定与 Stage-to-Core 准入门槛**：所有接入资料必须物理固化为带 SHA-256 哈希的只读 `.blob` 文件，未通过权威核验前严禁进入六步正式事实。

## 二、 系统架构上下文与依赖关系

### 1. 前置依赖 (Inputs From Upstream)
- 外部公开网络与授权 MCP 只读端点：提供原始 HTTP 报文、JSON 响应与 PDF 文件。
- `data/browser-search/`：提供 AI 浏览器人工/自动化核验回执。

### 2. 后置消费 (Outputs To Downstream)
- `data/catalog/`：存储标准化对象库与索引元数据。
- `financial_core/` 与六步研究 Schema：经 Stage-to-Core 准入审核后，消费经清洗的标准化财务序列。

### 3. 数据流转时序图
```
┌──────────────────────────────────────┐
│  外部数据源 (免配置公开来源 / 浏览器) │
└──────────────────┬───────────────────┘
                   │ (读取 Source 配置并调度 Job)
                   ▼
┌──────────────────────────────────────┐
│  数据接入暂存网关 (Staging Gateway)   │
│  ├── 固化原始报文为不可变 Artifact   │
│  ├── 计算 SHA-256 并生成摘要 Result  │
│  └── 关联 BrowserReceipt 官方核验回执 │
└──────────────────┬───────────────────┘
                   │ (严格核验证据版本与单调时间)
                   ▼
┌──────────────────────────────────────┐
│  晋升至正式研究知识库 (Core Fact DB) │
└──────────────────────────────────────┘
```

### 2. 核心数学模型推导

1. **不可变对象 SHA-256 指纹校验方程**：
   $$\text{Digest} = \text{SHA-256}\Big(\text{BinaryChunk}_1 \,\|\, \text{BinaryChunk}_2 \,\|\, \dots \,\|\, \text{BinaryChunk}_N\Big)$$
   断言要求：单次落盘必须经由流式分块哈希，且落盘后文件字节数与 `byte_size` 严格相等。
2. **多版本重述时间单调递增约束**：
   $$t_{\text{acquired}, v+1} > t_{\text{acquired}, v}, \quad \text{version}_{k+1} = \text{version}_k + 1$$
   对于发生会计差错更正或报表重述的事实，必须作为新增版本追加，禁止原地 `UPDATE`。

## 五、 状态机与任务结果生命周期 (Result State Registry)

### 1. 暂存层任务执行结果状态空间

| 状态代号 | 英文枚举标识 | 中文状态名称 | 判定特征 | 准入处理策略 |
| :--- | :--- | :--- | :--- | :--- |
| `ING_01` | `collected` | 采集成功 | 报文解析成功，至少生成 1 条有效记录。| 允许进入暂存库等待审核。 |
| `ING_02` | `no_data` | 有效无数据 | 请求合规，上游明确无对应记录。 | 标记为空，禁止伪造填充。 |
| `ING_03` | `needs_config` | 凭据缺失拦截 | 接口需要商业 Key 或身份认证。 | 阻断调度，生成补数清单。 |
| `ING_04` | `rate_limited` | 触发上游限流 | 收到 HTTP 429 响应或连接超限。 | 退避重试，记录调度告警。 |
| `ING_05` | `corrupted` | 文件损坏坏块 | SHA-256 校验失败或文件不完整。 | 物理隔离坏块，禁止引用。 |

### 输出字段逐项业务释义
| 输出字段名称 | 字段标识 | 数据类型 | 计量单位 | 业务释义 |
| :--- | :--- | :---: | :---: | :--- |
| 原始文件编号 | `artifact_id` | `str` | 字符串 | 暂存层不可变对象全局业务主键。 |

## 附录：工程实现与边界自查清单 (Engineering Defense Checklist)

- [ ] **严禁在暂存层篡改原始字段名**：所有外部供应商采集的原始键值必须保持原汁原味，严禁在 `result.md` 中私自捏造统一定义。
- [ ] **原始归档文件严禁物理覆盖**：新抓取的数据若产生内容变动，必须新建独立 `.blob` 并递增版本号，严禁覆盖历史原始文件。
- [ ] **哈希指纹必须实时双重核验**：文件写入磁盘后必须立即回读并核对 SHA-256，与预期不符必须即刻抛出 `IntegrityError`。
- [ ] **严格的零越界路径引用保护**：所有 `storage_path` 与 `records_path` 必须解析为相对项目根目录的标准路径，严禁任何越界相对路径。
- [ ] **浏览器回执与文件双向锚定**：通过浏览器补数导入的官方原版文件，必须在 `browser-receipt.json` 中登记对应的确切文件路径与校验哈希。
